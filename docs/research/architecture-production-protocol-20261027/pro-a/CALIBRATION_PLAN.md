# 用真实项目校准，而不靠追问改变推荐

本轮唯一推荐是证据驱动的并行架构收敛协议。它有历史支持的机制，也有尚未测量的投入政策。校准的目的，是用可核查结果调整这些具体政策，不是在每次普通追问后重新发明整套流程。

## 1. 哪些预测必须接受检查

| 预测 | 如何观察 | 失败或反证的含义 |
|---|---|---|
| 必须串行的波次下降 | 记录真实任务依赖与等待；按相似范围和问题类型比较 | 调查只是提前增加一层，综合／再审仍全串行，需简化调度 |
| 实施→设计返回下降 | 只计原有重大设计缺口导致的返回，新需求和局部bug分列 | 关键前提仍在正式实施后首次调查，核心机制未改变 |
| 首稿结构缺口更多由作者自行关闭 | 独立调查前保存候选及自检记录，追踪owner／consumer／机制缺口 | 仍由Work反复补空字段，合同没有成为设计过程 |
| Work更多发现真正盲区 | Finding按新场景／新证据／局部一致性／无关／误归因分类 | 大量重复和低价值finding，降低或取消该类任务的默认Work |
| Codex临时核心决定减少，目标为零 | 记录接手未决项、实施中实际选择、来源与责任裁定 | 让Codex自行选择算法／恢复／产品语义即违反核心承诺 |
| execution-ready后重大reset减少 | 保留每次冻结的范围和前提；追踪后来失效原因 | “假Freeze”仍存在，需修证据门，而不是再加泛审 |
| 迟发现的返工更局部 | 对比受影响owner、接口、能力、撤回代码及可保留证据 | adapter只是名义分层，重新检查ownership和依赖 |
| 用户介入和协调下降 | 原始目标之后的提醒、解释、催促、转述、选下一模型分列 | 系统仍把角色调度交给用户，或报表本身制造负担 |
| 质量不因减少审查下降 | 冻结后重大缺口、误放行、错误阻塞、实际产品／科研结果同时记录 | 单纯更快不足以支持采用 |

这些是方向性预测，尚无数据支持“下降20%／50%”等幅度。D_codex目标为零是职责约束，不是本轮已经观察到的统计结果。

## 2. 先把历史基准做成真正可用的对照

本轮24条记录用于确定题型和真实后果，不全部用于估计效果。成稿后的两次输入隔离微回放已保留独立预测，但没有完整流程对照，仍不足以估计效果。优先从Bridge和Slurm中已有精确输入白名单的题构造封闭包，另外保留CAT数值与STAT局部bug对照。把Mica当前investigation、追加chronicle、缺原始输入的Clear Writing题降为开放历史分析，直到来源资格补齐。

每题分三层：当时可读原材料；参试者尚未见到的未来结果；独立裁判使用的影响与归因依据。提示不透露“这是Hook fail-open题”一类答案，文件和工具只允许读取cutoff。参试者先提交冻结判断、具体缺口、唯一下一动作及理由，再揭示结果。直接看到后续报告的现有研究者不能充当盲测参试者。

模型无法复原历史宿主时，不伪造运行。可以评分它是否提出了正确区分性probe、是否阻止过强主张；不能把“提议实验”计为“实验已发现”。若要比较实验带来的路线变化，所有条件收到同一份真实历史实验输出，记录这是受控证据揭示而非各自重新运行。

分开评估两个时点：结果前能否避免错误Freeze；结果后能否正确判作新需求、局部bug、证据缺口或架构失效。STAT未来代码bug不能在设计cutoff被要求猜中；正确的事前答案可能是准许有界实施并设置正向oracle。

## 3. 公平的比较条件

至少比较三项：正确执行现行1.7合同的Planner–Critic；单设计加结构闭合；本轮动态协议。第二完整设计的收益作为独立分组，不与同时新增probe／Work的收益混算。

每项获得相同原始资料、同等工具能力、相同实际权限、可比预算和质量要求。传统基线可以主动要求probe，也可以按现行规则局部返回Codex；不能为了赢而禁止它使用成熟能力。新协议必须计入所有隐藏成本：初始阅读、Work、第二设计、综合、冷读、脚本维护和最终验收。

同时做两种比较：固定资源预算下的质量与用户负担；达到同一质量门所需的实际资源和关键路径。模型、上下文长度、队列拥塞和真实runtime变动要记录。不同路线任务不能仅比token数，探针费用和用户授权等待也要分开。

输出盲去方法名后，由未参与候选的评估者依据原始来源判定高影响finding。不能让新协议自己写出的“应该命中清单”成为唯一真值；随后独立Work需要检查分类、来源和严重度。分歧保留理由，不能为了统计干净强制一致。

## 4. 真实项目试点怎样避免额外浪费

先选一小批已准备开展的任务，覆盖局部S、成熟跨组件M、复杂产品L、外部runtime或科研XL。初轮可取6–8个不同任务作为工程检查规模；这是 **ASSUMED试点规模**，没有功效分析，不能凭它估计普遍失败率。

设计阶段可以在同一目标上运行两个影子流程，均不实施生产；主负责人只采用一份最终设计。正式实施不为对照重复建设两套产品。真实返工的因果比较因此需要后续跨任务匹配或在获准试点中分配流程，不能由一次影子设计直接推出R_rework改善。

选任务时预先记录规模、原有材料质量、外部运行依赖、不可逆程度与历史耦合，避免新协议拿简单任务、传统流程拿事故项目。优先用现有result、commit和调用时间记录，不要求用户天天填表。用户实际阅读分钟没有可靠日志时保持UNKNOWN，可一次性自愿回顾，不能用文档字数换算精确分钟。

## 5. 最小记录与归因

每个正式任务保留一份简短事件记录，复用原任务文件：事件时间、当前范围／版本、动作及执行者、依赖、投入、取得的新事实、改变的决定、是否需要用户、是否让已有实现失效。相同问题使用同一ID；同类finding重复只记复验次数，不增加独立缺陷数。

冻结时固定已知能力、前提、证据和未覆盖范围。后续发现由Chat依据原要求归为DESIGN_GAP、NEW_REQUIREMENT、EXTERNAL_FACT、IMPLEMENTATION_BUG、REVIEW_DRIFT、SCOPE_RESET、EVIDENCE_GAP或OTHER，可多标签但保留主因。“Critic遗漏”另记录其实际审查范围与材料；不能仅由后来出问题倒推某位审查者失职。

代码撤回保留具体diff、原因、后续重用情况；有开发分钟就记录，没有就仅给行数／模块代理。删除测试、替换接口、移文件、真正废弃逻辑分别标注。用户新增需求造成的合理修改不计原设计失败，但仍计实际成本以反映用户体验。

## 6. 如何逐步更新参数

初期不估细粒度p/q。先按任务族、失效机制和严重度给OBSERVED事件计数，保留UNKNOWN的分母；以明确案例复核分类错误。样本不足时用低／中／高和宽区间，不用主观数字做“实测后验”。

有足够重复任务后，估计有条件的量：某类关键前提被probe反证的比例；Work独有高影响发现与误阻塞；第二Pro改变决定的原因；同类事实出现后重开了多少owner；用户为调度多做了几次动作。明确分母是哪些任务，不能把不同项目、不同版本和同一事故重复记录混为独立样本。

可报告配对差值、项目聚类后的分布和宽区间，保留异常值。未达到可比数据条件就不报告统计显著或概率保证。常规线上任务的探索／利用配比另行设定，不能为了估计检出率故意放过安全或科学阻断项。

## 7. 哪些证据会改变推荐

**保留核心，调整投入。** 若Work在某类成熟项目中持续没有独有高影响信息、却制造误归因和阅读成本，该类降为单设计＋结构闭合＋定向核查。若第二Pro能稳定发现Work和主设计都没有的全局路线，并在同预算减少后续返工，则把该类任务的第二设计前移为默认。第三Pro仍需独立问题，不因一次多数投票胜出成为固定角色。

**修改机制。** 如果关键runtime在完全遵循本协议时仍因相同入口／故障范围缺证而获Freeze，立即修订证据判据和执行约束，不等待积累多个事故。如果结构合同高成本、易填空投机，缩减到真正改变决定的对象并加强直接证据；不不断加字段。若probe诱导团队保留实验代码或过早锁路线，改为预登记淘汰条件、显式可丢弃实现和替代路线保留。

**撤回整体默认。** 若强化Planner–Critic在可比任务与资源下保持相同或更低G_gap、D_codex、R_rework，同时有更少H_user和T_wait，则撤回动态协议的优越性主张，采用更简单方案。若Bridge／Slurm关键反事实经独立核证不成立，降低相关机制的证据强度，重算优先级。某任务族无法适配时明确限制适用范围，不强行统一。

普通追问、角色偏好和单次低影响finding不构成改推荐的证据。改变必须写明新的来源、影响哪个预测、为何原判断不再适用，并只调整相关条款。

## 8. 本轮结束后的唯一下一位

本轮pro-a完成后，接收者是用户已安排的**独立Work历史证据核查结果的汇合裁决者（Chat／主研究主持者）**；它将本候选与独立Work事实对照，再决定采用及试点，不让用户重新发明路由。本研究没有读取该Work或另一Pro结果，也不自行把本候选写进生产角色合同。

核查的首要问题是：BR-01／BR-03及S-RUNTIME／S-AUTH是否有真实cutoff支持；新法是否对routing和STAT普通bug过度升级；用户延期和新需求是否被公平保留；当前Asteria能力是否被夸大；全部模型和维护成本是否计入。来源与规则都已经写成可被推翻的具体主张，后续不需要用户再解释研究目标。
