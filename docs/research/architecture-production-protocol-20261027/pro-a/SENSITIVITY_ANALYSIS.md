# 信息价值、敏感性与用户成本

本研究没有实测“重大遗漏概率”“第二 Pro 检出率”或“减少返工百分比”。历史能证明具体事件及部分成本代理，不能给这些概率提供可靠分母。本文件用明确标注的假设分析推荐何时稳定、何时应取得更多信息，避免用一组漂亮数字替代证据。

## 1. 目标函数和硬边界

优先减少用户介入、关键路径等待、实施后架构返回和失效实现，同时保持核心产品／科研正确性。AI 调用成本受实际预算约束，但不是默认第一优化项。未经授权的副作用、静默改需求、未决核心机制转给 Codex、关键证据未知却宣称成立，都属于硬边界，不能用一个较低的预计出错概率抵消。

可以在可行方案内部比较向量 \((H_{user},T_{wait},R_{rework},B_{blast},D_{codex},C_{ai})\)。若某方案在所有重要维度都不差且至少一项更好，优先它；如果有真实取舍，就采用用户已表达的优先级并说明，而不暗中给所有指标设货币权重。无法比较时取得针对性信息，不让用户替系统选择每个模型。

## 2. 参数怎样观察

| 参数 | 可操作定义 | 本轮证据身份 |
|---|---|---|
| `N_design` | 独立完整方案数；只做核心路线草案另记，不凑完整方案数 | 历史全部调用 UNKNOWN；本协议默认值为政策选择 |
| `N_review` | 独立检查任务数；区分盲查、冷读、成品验收、同 finding 复核 | 可见审查文档数 OBSERVED，模型任务数 UNKNOWN |
| `N_probe` | 不同区分性事实问题数；执行次数另列 | 部分命名实验 OBSERVED，不等于所有尝试 |
| `S_serial` | 实际依赖图上必须依次完成的模型／实验波次 | 逻辑依赖可 INFERRED；完整会话边界 UNKNOWN |
| `P_parallel` | 实际同时推进且能产生独立结果的任务数／峰值 | 历史时间数据不足，UNKNOWN |
| `H_user` | 用户主动分钟、决策次数、提示继续、转述失败及转交次数分列 | 有文档痕迹；精确次数和分钟 UNKNOWN |
| `C_ai` | 实际计费／额度、token或模型分钟，保留模型与工具类型 | UNKNOWN；不以报告数替代 |
| `T_wait` | 从可开始到必要结果到达的关键路径等待，区分模型运行、排队、用户等待 | Git 时间差不是该值；UNKNOWN |
| `R_rework` | 冻结后因原有重大设计问题发生的修订工作；新需求单列 | 可定位事件及下界，实际工时 UNKNOWN |
| `B_blast` | 一次事实失效影响的能力、owner、接口、消费者及证据范围 | 可从明确依赖 INFERRED；不只数文件 |
| `D_codex` | Codex 被迫决定的核心产品／算法／owner／恢复／验收问题；记录严重度 | Mica Goal 有职责转嫁代理；总数 UNKNOWN；目标为 0 |
| `F_drift` | 经核源裁定的无关、错误归因或越出范围 finding | 有具体正反例；总体比例 UNKNOWN |
| `G_gap` | 冻结后发现的重大旧设计缺口；排除新增需求和普通编码 bug | 有事件；总体率 UNKNOWN |
| `I_impl` | 稳定前正式实施启动的不同 episode；探针不算 | Bridge 可见代码 cohort 是下界代理，非会话数 |
| `A_reset` | 改变整体范围／核心责任结构的重置；局部设计修订另计 | Bridge 明确至少一次；其他按证据逐项分类 |
| `W_waste` | 因架构改变而撤回／替换的实现，保留原因、后续重用及成本 | 部分删改行 OBSERVED；工时和全仓比例 UNKNOWN |

同一事故的多个 commit、review 和 bug ID 不能当独立样本。把 `N_review` 降低但 `G_gap` 提高不算成功；把需求删掉使 `W_waste` 变小也不算成功。[历史指标与限制](HISTORICAL_BENCHMARK.md)。

## 3. 信息价值的完整思想与可计算简化

令 \(E\) 为当前证据，\(d\) 为可选架构决定，\(\theta\) 为未知事实，\(a\) 为下一调查／实验，\(y\) 为其可能结果。理想的信息价值是取得信息后最优决定的损失下降，再扣除调用、人类参与和等待：

\[
V(a\mid E)=\min_d\mathbb E[\ell(d,\theta)\mid E]
-\mathbb E_{y\mid E,a}\!\left[\min_d\mathbb E[\ell(d,\theta)\mid E,y,a]\right]
-c_a-\lambda_H\Delta H_a-\lambda_T\Delta T_a.
\]

这是决策定义，不是本轮已估计的量。实际概率、损失、单位转换和权重全部 **UNKNOWN**。有时信息的价值是证明当前路线不应继续，有时是证明无需另开审查；不是发现越多越好。

用于敏感性演示的简化设定：\(p\) 为某相关重大缺陷存在概率；\(q\) 为缺陷存在时调查取得可行动发现的条件概率；\(L\) 为未及早发现的损失，\(R\) 为发现纠正后的残余损失；\(c\) 为可比成本。假定 \(L>R\)，则

\[
\Delta=pq(L-R)-c,\qquad k=\frac{c}{L-R},\qquad \frac{\Delta}{L-R}=pq-k.
\]

若要纳入误报、错误修订和额外协调，必须再扣除其预期损失；当前小模型没有这些项，不能当成自动批准规则。若 \(L=R\)，调查不降低该类损失，不能使用此归一化。

## 4. 宽范围假设：推荐不是由某个单点数字推出

下表所有数值均为 **ASSUMED**。真实 \(p,q,k\) 仍 **UNKNOWN**。表中是 \(pq\)，代表达到盈亏平衡所允许的最高成本比例；不代表已测的模型准确率。

| 假设缺陷概率 \(p\) | 假设检出率 \(q=0.1\) | \(q=0.4\) | \(q=0.8\) |
|---|---:|---:|---:|
| 0.02 | 0.002 | 0.008 | 0.016 |
| 0.10 | 0.010 | 0.040 | 0.080 |
| 0.50 | 0.050 | 0.200 | 0.400 |

再令成本比例 \(k\) 分别为 0.01、0.05、0.20、0.50，得到 36 组正／零／负结果。低风险、昂贵调用时，多开模型往往没有合理依据；大损失、便宜且区分性强的试验更容易值得。任何一格都不能被解释为该项目实际风险。“36 格中多少格为正”也不是值得行动的概率，因为网格没有抽样分布。

这里没有一个固定模型数量在所有合理参数下占优。因此推荐的稳定部分是**按具体问题选信息来源与停止**，而不是始终两份或三份完整设计。一个 Pro＋一个 Work 是当前复杂项目组合下可校准的初始政策；它没有被这张任意网格“数学证明最优”。

若合理区间里 \(pq-k\) 全为正，可优先调查；全为负则不安排该非必需调用；跨零则检查哪一项未知最影响决定，先用廉价来源收窄它。关键冻结硬条件仍未满足时，即使某昂贵试验不划算，也只能选更便宜证据、隔离边界、限定范围或停止，不能直接声称安全／科学前提成立。

## 5. 多位设计者的相关失败

对同一固定缺陷，令

\[
q_i=P(\text{第 }i\text{ 位检出}\mid\text{缺陷存在，前 }i-1\text{ 位均漏检}),
\qquad m_N=p\prod_{i=1}^{N}(1-q_i).
\]

这是条件概率链式分解，不要求独立。不能把单人总体检出率直接代入每个条件 \(q_i\)。前面全漏事件概率为零时剩余风险已为零，无需定义该零概率条件。修订产生新缺陷时，还需要新缺陷项，不能只乘原缺陷的存活概率。

为了看共享盲区的影响，另作一个 **ASSUMED** 混合模型：比例 \(s\) 的缺陷会被全部审查者共同漏掉，剩余部分才按同一 \(q\) 独立发现。于是

\[
\frac{m_N}{p}=s+(1-s)(1-q)^N.
\]

\(s\) 是假设的共同漏检缺陷占比，不是 Pearson 相关系数。令假设 \(q=0.6\)：

| 假设 \(s\) | 一位后 \(m_1/p\) | 两位后 \(m_2/p\) | 三位后 \(m_3/p\) | 第二位边际减漏／\(p\) | 第三位边际减漏／\(p\) |
|---|---:|---:|---:|---:|---:|
| 0 | 0.400 | 0.160 | 0.0640 | 0.240 | 0.0960 |
| 0.5 | 0.700 | 0.580 | 0.5320 | 0.120 | 0.0480 |
| 0.9 | 0.940 | 0.916 | 0.9064 | 0.024 | 0.0096 |

表格只说明一种共同盲区下的机制：再增加同类判断无法消除共享错误前提。Bridge 的 reader 和 Slurm 的 host failure 是实际存在的共享前提候选；对它们，换成直接观察可以改变信息来源。历史尚未测量 \(s\)，也没有证明第二 Pro 的平均收益一定低于 Work。

## 6. 并行减少的是依赖等待，不自动减少总成本

给定任务依赖图，资源充足且无额外争用时，关键路径长度为

\[
T_{critical}=\max_{\pi}\sum_{a\in\pi}t_a.
\]

可复算示例采用**同一任务集合**：主设计 60、Work 40、probe 30、综合裁决 30、冷读 20 分钟，全部是 **ASSUMED**。前三项原始输入已齐且可独立，后两项依次等待其前置。强制串行是 180 分钟，允许前三项并行是 \(\max(60,40,30)+30+20=110\) 分钟。总任务时间仍为 180 分钟。

70 分钟只是这个人造依赖图的差，不是新协议相对 Planner–Critic 的实测节省。若 probe 必须先获得设计结果，或者并发资源不足，应加入依赖／资源约束重算；若综合多方案更费时，也要计入。不能拿不同任务集合的时长相减来宣称公平对照。

## 7. 降低影响范围会改变值得调查的阈值

架构隔离降低 \(L-R\) 时，同样调查成本的 \(k\) 上升，因此更多重型调用可能不再必要。这并不与风险优先冲突：先把必需保证守住，再减少遗漏后的损失，可以同时减少模型投入和返工。

但隔离有成本，adapter 可能引入新接口、配置和运维负担。不能把每个未知包成一层后就宣布安全。实际需比较替换影响是否从多个 owner 缩到一个边界，旧能力是否保留，故障是否真的不传播。Bridge 的表达／传输边界和 Slurm 的无关命令保护提供具体检验题，详见专项报告。

## 8. 哪些结论稳定，哪些需要校准

| 结论 | 当前稳定程度 | 会改变判断的证据 |
|---|---|---|
| 用具体外部证据回答可观测的关键事实 | 多案存在直接反事实机会和早期 probe 正例 | 同等条件的 probe长期不能区分路线、成本异常高或造成锚定 |
| 不用字段齐全／PASS代替实际证据 | Bridge／Slurm 强支持 | 未发现能支持相反充分性的证据 |
| 局部 bug 留 Codex，核心机制返回 Chat | 角色边界及多案支持 | 当前问题被误分类，修复实际改变了合同 |
| 尽早并行独立输入已齐的工作 | 依赖图性质成立，真实幅度未知 | 并发争用／协调成本超过等待收益 |
| L 默认一个 Pro＋一个 Work | 合理政策选择，尚无实测最优性 | 同成本独立 Work低增量，或第二完整设计稳定更有价值 |
| 第三完整设计者非常规调用 | 相关失败模型与证据类型支持克制；平均收益未知 | 实际出现第三种重要路线／专业能力且贡献可复核 |
| Asteria 减少首稿显性洞与维护成本 | 结构机制可信，净收益尚未前瞻测量 | 维护成本、误阻塞或字段投机抵消收益 |

复算见 [analysis/sensitivity.py](analysis/sensitivity.py) 与 [evidence/sensitivity_results.json](evidence/sensitivity_results.json)。脚本使用标准库 Decimal，检查平衡点、单调性、边际减漏和依赖图；输出通过不代表假设真实。下一步如何校准而非任意换数字，见[校准计划](CALIBRATION_PLAN.md)。
