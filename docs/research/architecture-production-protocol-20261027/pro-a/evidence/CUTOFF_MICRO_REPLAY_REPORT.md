# 两次输入隔离微回放

为检查历史分析是否只是在知道答案后解释，主研究在成稿后追加两次新上下文判断。两个执行者均以 `fork_turns=none` 启动，没有收到父研究对话、用户已提示的后续事故或本候选协议；只给中性编号目录中的原始cutoff文件。指令允许判断已经足够，不要求找出缺陷；要求给唯一下一执行者，最多八项实质问题，不运行产品、不读其他文件或网络。

这是**输入隔离的有限微回放，不是完整工作流盲测或公平效率对照**。主研究已知结果并选择题目；输入限制由指令而非独立操作系统权限强制；执行者报告遵守；判断由知情父研究事后定性核对。每题只有一次判断，没有基线组、匹配预算、独立评分者或真实历史runtime。

## 这项补充能支持什么

它支持一个比纯回顾推断略强的结论：在这两份真实cutoff材料上，未见后续结果的新上下文执行者能够指出关键未知，并选择事实／实验动作。它也支持保留独立语义审查的价值：Slurm题本来就是历史Critic发现过的实质权限问题。

它不能证明本协议优于正确执行的Planner–Critic。执行者没有运行任何一整套候选流程；相同能力也可能属于传统Critic。不能把“两份判断都提到相关问题”转换为100%检出率，不能估计串行等待、人工时间或返工降低幅度，也不能把建议probe写成probe已经成功。

24条主案例记录仍按retrospective资料使用。两份补充预测另外保存，不倒签为原历史Freeze前发现。未来严格比较仍按[校准计划](../CALIBRATION_PLAN.md)执行。
