# 不确定性与敏感性分析

## 1. 原则

本研究不把未知的“重大遗漏概率”“模型检出率”“返工损失”写成伪精确数字。每个量必须标注来源状态：

- `OBSERVED`：历史记录直接支持；
- `INFERRED`：由观察事实合理推得；
- `ASSUMED`：为了比较而设定的情境；
- `UNKNOWN`：当前证据不足。

如果一个推荐只在某组任意数值下成立，不采用。只有在宽范围情境下方向稳定，或敏感变量可被优先取证，推荐才足够强。

## 2. 决策框架

对候选下一步 \(a\)，概念上的净信息价值为：

\[
\operatorname{NIV}(a)
= P_a(\text{改变正确决策或提前避免重大返工})
\times L_a
- C_a
- \lambda T_a,
\]

其中：

- \(P_a\)：该调用/实验产生决策相关信息的可能性；通常 `UNKNOWN`；
- \(L_a\)：若提前发现问题可避免的损失；用低/中/高 blast 与返工代理描述；
- \(C_a\)：AI、实验和协调成本；
- \(T_a\)：关键路径增加；
- \(\lambda\)：用户对等待时间的权重。本用户明确更在意等待、协调和开发后返工，而不是总调用次数，因此 \(\lambda\) 不低。

该式用于组织判断，不用于伪造精确期望值。实际 selector 采用序数尺度和支配关系。

## 3. 已观察与未知量

| 变量 | 当前状态 | 证据 |
|---|---|---|
| 固定 P–C 的串行轮数较高 | `OBSERVED` | Bridge、Slurm 多轮 proposal/review/revision/implementation |
| 高 blast 外部事实可在晚期推翻架构 | `OBSERVED` | Slurm Hook runtime；CAT-TRACE 数值近似 |
| Asteria 能发现 owner/payload/consumer/source-anchor 空洞 | `INFERRED`，有结构回放支持 | Bridge、Mica、STAT5060 反事实映射 |
| Work 独立盲区的平均 precision | `UNKNOWN` | 尚无统一前瞻样本 |
| 第二 Pro 改变核心路线的频率 | `UNKNOWN` | 有少量设计研究，缺统一统计 |
| 最小 probe 避免返工的平均收益 | `UNKNOWN`，案例支持为高 | Slurm/CAT/Bridge 个案 |
| 固定 Critic 的高影响 finding 比例 | `UNKNOWN` | 历史文档未统一编码严重度 |
| 架构返修废弃代码比例 | `UNKNOWN` | Bridge 有明显方向性证据，缺行级归因 |
| 用户协调时间 | `UNKNOWN`，方向可观察 | 对话与多轮提交显示高，但无计时 |
| adapter 边界降低 blast radius | `INFERRED` | 软件架构机制与历史反事实支持 |

## 4. 情境变量

为比较流程，使用下列宽情境而非单点概率：

### 4.1 漏项风险 \(p\)

- 低：局部、成熟、已有接口与同类实现；
- 中：跨组件、历史要求多，但技术路线清楚；
- 高：跨仓库/权限/平台/科学算法，或用户已多次发现遗漏。

### 4.2 独立设计增量 \(q_D\)

- 低：路线几乎唯一，第二设计者很可能复述；
- 中：存在局部替代，但可通过事实调查裁决；
- 高：存在互斥产品/科学路线，且不同路线会改变大部分实现。

### 4.3 盲区调查增量 \(q_W\)

- 低：原始材料少、范围单一、历史事故清楚；
- 中：跨功能 TODO 与用户反馈较多；
- 高：长期项目、多个历史版本、多个真实使用表面或多仓库。

### 4.4 探针增量 \(q_P\)

- 低：外部事实已有当前一手证据；
- 中：事实未知但错误可局部吸收；
- 高：未经验证的 runtime/API/数学前提一旦错误会推翻核心架构。

### 4.5 返工损失 \(L\)

- 低：一个文件、无迁移、可回滚；
- 中：多个模块、部分接口或验收器；
- 高：跨仓库、权限、安全、数据、平台、数月科研或大量已写代码。

## 5. 流程在宽情境下的比较

### 5.1 低风险局部任务

假设：\(p\) 低、\(L\) 低、所有 \(q\) 低。

- 固定 Planner–Critic：额外串行成本明显，收益小；
- 两个 Pro：重复劳动；
- Work：材料整理成本高于收益；
- Asteria 轻量自检 + 直接 Codex：占优。

结论对参数不敏感：S 任务不应升级成多模型流程。

### 5.2 跨组件但路线成熟

假设：\(p\) 中、\(L\) 中、\(q_W\) 中、\(q_P\) 低/中、\(q_D\) 低。

- 固定 P–C 能发现问题，但串行；
- 主设计 + Asteria + 按需 Work/fact check 可并行，且第二 Pro 增益低；
- 冷实施挑战可在代码前发现 handoff 空白。

结论稳定：M 默认一个主设计，不固定第二 Pro。

### 5.3 高 blast 外部 runtime

假设：\(p\) 中/高、\(L\) 高、\(q_P\) 高；\(q_D\) 从低到高均可。

无论第二 Pro 的检出率多高，只要多个模型共享同一未验证 runtime 假设，第三个设计者都不能替代 probe。Slurm Hook 是直接证据。

结论稳定：先并行设计与最小 probe；未经 probe 不 Freeze。

### 5.4 高 blast 产品路线竞争

假设：\(L\) 高、\(q_D\) 高、事实不能单独裁决。

- 一个主设计 + Critic 容易继承路线；
- 两个独立完整设计并行能拓宽备选；
- Work 检查用户场景与历史事故；
- probe 只验证各路线共同或差异化前提。

结论稳定：启动第二 Pro，但不固定第三 Pro。

### 5.5 长历史、跨仓库、显性遗漏风险高

假设：\(q_W\) 高、\(L\) 中/高。

即使 Work 的低价值 finding 比例不小，只要严格要求“证据、影响、是否改变架构、严重度”，独立原始输入调查仍可并行完成，不显著增加关键路径。Bridge/Delivery Assurance 支持该判断。

结论稳定：L/XL 默认 Work 盲区；若未来 precision 持续很低，再收紧触发器。

## 6. 第二 Pro 的边际收益

设独立设计者数量为 \(N_{design}\)。不能假设独立错误，因此收益不会按 \(1-(1-p)^N\) 简单增长。多模型可能因相同训练、相同材料和相同术语高度相关。

采用以下序数判断：

| 条件 | 第 2 Pro | 第 3 Pro |
|---|---|---|
| 唯一路线、外部事实未知 | 低 | 极低；应 probe |
| 两条互斥高 blast 路线 | 高 | 低/中 |
| 两个方案一致但共享未证假设 | 低 | 极低；应 probe |
| 两个方案明显冲突且证据不足 | 已完成 | 仅当第三套独立证据源可能裁决；优先 Work/事实调查 |
| 科学路线与产品价值同时不确定 | 高 | 可能中，但需明确不同研究视角 |

默认 `N_design=1`；触发后为 2；3 不是常规档位。

## 7. Work finding 低价值风险

Work 的风险是把所有 TODO、边界和历史都转为 finding。为控制 `F_drift`，每项 finding 必须回答：

1. 原始证据是什么；
2. 哪个真实用户场景受影响；
3. 若不处理，最坏后果与 blast radius；
4. 它属于缺口、事实、实现 bug、产品选择还是新需求；
5. 是否会改变核心架构；
6. 最低成本的下一信息来源是什么。

只有高影响且未被候选处理的 finding 阻止 Freeze。低影响 finding 进入 local issue，不触发新架构轮次。

在 Work precision 从保守低值到乐观高值的宽范围内，只要它并行运行且有严重度门槛，其成本主要是 AI 调用而非用户等待；因此 L/XL 默认保留仍然稳健。

## 8. Asteria 维护成本敏感性

Asteria 的收益取决于结构记录是否为设计本身的最小合同，还是额外复制一份报告。

### 低成本实现

- 只记录稳定对象、关系、机制、anchor、evidence、issue、revision；
- 与正式设计同仓；
- 静态生成；
- 不要求每个 commit 更新；
- 只在 meaningful revision 维护。

此时它替代显性 Critic finding 和手工交接表，预期净收益为正。

### 高成本实现

- 新建后台、数据库、账号、在线编辑器；
- 复制源码和全部文档；
- 每个微小实现变化都维护；
- 图与设计各写一份；
- 需要专人同步。

此时成本可能超过收益。Architecture-evolution 两个独立研究均建议停止在 Git 原生薄层，因此最终协议只采用低成本形态。

若真实试点显示维护一次 revision 的人工时间持续超过其节省的架构理解/返工时间，应缩减字段或停用，而不是扩建平台。

## 9. Probe 过早锁定错误路线的风险

最小 probe 不能回答产品价值，也不应把第一种可运行实现自动升级为架构。控制规则：

- probe 只验证明确假设；
- 不实现完整产品；
- 输出事实与限制，不给未经授权的产品决定；
- 至少包含一个失败路径；
- 结果返回主架构师比较路线；
- 可替代 adapter 的 probe 不冻结核心接口之外的实现细节。

在此约束下，即使 probe 结果阴性或路线后来变化，其成本仍局部。相反，Slurm/CAT 历史表明不 probe 的潜在损失很高。

## 10. 决策稳健性表

| 合理未知取值 | 推荐是否变化 |
|---|---|
| 第二 Pro 平均增量偏低 | 不变化；继续只在高 blast 路线竞争时触发 |
| Work precision 偏低 | 不变化但收紧 finding 门槛；若接近零再取消默认 |
| Asteria 成本中等 | 不变化；限制为薄层并替代其他表格 |
| probe 成本中等 | 对高 blast 仍保留；低 blast 不触发 |
| Critic 高影响检出率高 | 不恢复固定流程；把独立 Critic 作为 selector 的一种动作 |
| 实施返工成本低 | S/M 降级；L/XL 仍按范围判断 |
| AI 调用成本上升 | 优先保留并行的高信息来源，减少第三 Pro和低价值审查 |
| 用户等待成本更高 | 更支持并行首波与动态停止 |

## 11. 最敏感的未知量

当前推荐最值得未来校准的不是抽象“总体漏项概率”，而是三个可操作量：

1. **第二 Pro 在触发条件下改变核心路线的比例；**
2. **Work 高影响 finding 的 precision；**
3. **最小 probe 在 Freeze 前否定/修改杀手假设的比例及避免的返工代理。**

若这些量表现差，调整触发阈值；不需要推翻整个动态路由思想。

## 12. 结论

在低/中/高风险、低/高模型增量、低/高 probe 价值和低/高返工损失的宽范围下，结论稳定：

- 不固定运行 Planner–Critic；
- 不固定运行两个或三个完整 Pro；
- 用 Asteria 消灭显性结构缺口；
- L/XL 并行 Work 盲区；
- architecture-killer assumption 优先真实 probe；
- 高 blast 互斥路线才启动第二 Pro；
- 冷实施挑战通过后直接 Freeze；
- 下一次信息价值低时停止。

推荐对单个任意概率不敏感。真正敏感的未知量会被协议本身路由为下一条待获取信息，而不是藏在一个看似精确的评分里。
