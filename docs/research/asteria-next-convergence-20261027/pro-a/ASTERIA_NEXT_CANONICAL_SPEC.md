# Asteria Next：最终候选产品规格

**Asteria Next 是现有 Asteria 的下一阶段：以 Git 中的设计和真实来源为基础，让用户从当前系统追到机制、实现、证据与局部演变，并在架构冻结前看见尚未决定的关键行为。** 产品继续叫 Asteria。它采用一套 canonical semantic model，保留科学模型、符号、变体、谱系与证据能力，扩展到软件和 Artifact 验收。

本文件给出本轮唯一候选。历史四版的逐项取舍见 [CONVERGENCE_DECISION_MATRIX.md](CONVERGENCE_DECISION_MATRIX.md)，具体数据契约见 [SEMANTIC_MODEL.md](SEMANTIC_MODEL.md)。本轮只完成研究和参考原型；正式 Asteria 没有修改，也未因本规格形成实施或发布授权。

## 1. 产品要让用户完成什么

面对一个复杂项目，用户默认先看当前系统，在保留全局位置的同时选择组件或关系。后续问题沿同一对象展开：它如何工作，谁消费结果，真实实现在哪里，证据支持到什么程度，它为什么改变，哪些东西没有改变，代码是否跟上当前设计。

Chat 通过同一材料设计架构：先明确用户能力与边界，再把责任、载荷、机制、失败与恢复、实现责任和验证方法逐步写实。Asteria 的检查指出具体缺口，帮助 Chat 在交给 Codex 前处理它们。遇到科学算法或产品选择尚未确定时，系统保留问题及阻塞范围，不替作者生成一个看似完整的答案。

产品长期承担四项工作：

| 工作 | 用户得到的结果 |
|---|---|
| 理解当前系统 | 可读的系统投影、节点上下游、可选关系、同一拓扑的任务路径 |
| 把架构设计到可实施 | 有责任与机制的组件、有载荷与消费者的交接、明确失败/恢复及验证责任 |
| 对照真实来源 | 固定源码、Skill 规则、科学公式、产品对象与证据，不同来源的权威分开 |
| 理解和维护变化 | 局部 before/after、触发依据、取舍、影响、未变保证及实现对齐情况 |

Asteria 阅读和核对已有材料，保存设计约束与来源关系。执行器、项目验收程序、科学计算、专业判断和原制作任务继续履行各自职责。账户、云数据库、图数据库、向量库和 Agent runtime 不进入本轮产品边界；现有运行环境可以继续承载界面和静态产物。

## 2. 为什么继续演进 Asteria

固定检查的 Asteria 为 `60ba27a38324980beea78d4c07b7b28abda522cf`，当前应用版本为 `2.0.0-rc.19`。它已经拥有独立实体与符号、类型化关系、变体、投影、上下游遍历、迁移与仓库绑定的基础。现有 React、React Flow、KaTeX 与产品外壳也可继续使用。这些能力与目标一致，未发现需要建立平行产品的核心冲突。[当前产品与边界][asteria-readme]、[语义类型][asteria-types]、[现有依赖][asteria-package]

需要改变的是具体约束与实现深度：

| 当前限制 | Next 的确定改法 | 为什么不必重造 |
|---|---|---|
| 实体必填科研层级，关系枚举以科研为主 | 保留原科学含义；展示分组可配置；扩展实体种类及按关系类型的契约 | 稳定实体与关系身份已经独立存在 |
| parser 对深层内容的校验不足 | 增加版本化 schema、可判别能力面和确定性迁移 | 可以沿现有导入边界补齐，不需要第二套数据库 |
| `diffOriginalTraceToCatTrace` 返回预写条目 | 使用真实快照、稳定 ID 和语义字段计算；作者解释附在结果上 | 原来的比较表达有价值，计算实现可以替换 |
| 证据状态依据支持边/缺口边计数 | 保留关系，依据对象版本、方法、结果和依赖计算适用性 | Evidence 已是语义图的一部分 |
| bridge 是合成固定提交样例，并要求至少一个绑定 | 泛化为共享锚点与规范化绑定，允许合法空集合，增加真实解析 | 既有 binding 字段和角色可迁移 |
| 不同视图选择不同样例实例 | 所有视图读取同一选定快照 | 投影层已有独立边界，可改会话选择而不丢语义 |
| 校验用自然语言 `role.includes` 或临时类型强转 | 按实体种类、机制类型、关系合同和正式绑定校验 | 可渐进替换规则，继续保留科学领域检查 |

这些限制来自本轮实际读取的[比较实现][asteria-diff]、[证据样例][asteria-evidence]、[仓库桥接][asteria-bridge]、[会话选择][asteria-session]与[校验器][asteria-validation]。它们要求真实迁移工作，不能只换类型名称或主题颜色。

1.x 的历史画布已退出 active runtime。Next 保护其输入格式、富文本与公式、变体、布局、叙事提纲和迁移回归，不恢复隐藏的旧产品入口。原冻结材料与恢复能力继续保留。[既有兼容范围][asteria-readme]、[旧格式回归][asteria-legacy]

## 3. 唯一模型和来源权威

核心保留 `project`、`entities`、`symbols`、`relations`、`variants`、`views`，新增共享 `anchors` 与 `revisions`，把现有 bridge binding 规范化为 `bindings`。组件、机制、要求、产物、决定、问题和证据使用同一实体身份及类型化能力面；没有独立的同义 Component、Mechanism、Evidence 或 Issue 根数据库。

原设计正文、源码、规则和结果文件继续维护在原位置。`.asteria/project.yaml` 只补必要的稳定身份、关系与正文选择器。确定性编译产生一份语义快照，所有视图、搜索、差异和检查读这份快照。作者不为网页再维护一份相同正文。完整作者入口、固定锚点及证据合同见 [SOURCE_BINDING_AND_EVIDENCE.md](SOURCE_BINDING_AND_EVIDENCE.md)。

| 内容 | 权威来源 | 冲突时的处理 |
|---|---|---|
| 用户能力、边界与设计决定 | 已接受的需求、设计和决策记录 | 保留来源分歧，交由相应负责人决定；代码现状不自动覆盖设计 |
| 实际文件、函数、selector、装配与消费位置 | 固定提交的源码及必要运行观察 | 显示实现观察与设计差异；工具可提出重绑建议，不能改责任定义 |
| 科学模型与命题 | 原模型定义、假设、证明与专业决定 | 实现或测试不能单独推翻或确认完整科学主张 |
| Artifact 内容与位置 | 精确候选文件、渲染产物、有序页面与对象定位 | 当前要求与候选分别保存；相同页码不能跨版本自动对应 |
| 验收要求 | 当前有权威的要求与规则版本 | 新要求可使字节未变的成品不再适用；历史接受仍保留其当时范围 |
| 已观察的结果 | 绑定候选、方法、条件和产物的证据记录 | 历史结果不可重写；重新计算其对当前对象是否适用 |
| 视图、索引与布局 | 从共同快照生成 | 可丢弃重建，不能反向成为设计真值 |

源码锚点固定仓库、提交、路径、结构选择器及可得的指纹；行号只用于跳转。Artifact 锚点固定候选摘要，再定位页、对象或区域。定位成功、歧义、缺失、不可访问分别记录。来源不可访问不等于文件删除，链接可打开也不等于语义已对齐。

## 4. 信息架构：三个主要入口

产品只有三个主导航：**当前架构、修订、检查**。项目选择保持紧凑，来源与版本按需打开。机制、实现和证据跟随选中对象，不成为首页上三个争夺注意力的大面板。

### 当前架构

桌面主体是系统图与按需出现的 inspector。可收起的目录提供查找和等价选择方式，系统图保留可读节点、关系标签和足够留白。初始没有被选中的对象时，画面让系统本身成为主体；不默认塞满解释产品用途、完成率和 reassurance 的卡片。

选择组件后，图中保留它的上下游位置，详情说明当前责任与最有用的机制入口。选择关系后，先回答传什么、由谁消费、何时发生，以及失败/恢复条件。关系可以继续导航到两端或具体机制步骤，点击标签和线段均有可用命中区域。

详情按当前对象提供：

- **机制：** 状态、时序、算法、公式或产物结构，选择适合内容的表达。
- **实现：** 当前绑定的实际来源、角色与定位状态。设计态明确没有实现，不制造占位函数。
- **证据：** 支持哪项结论、针对哪个版本、方法和范围、当前适用性。
- **局部变化入口：** 最近有意义的变化，继续进入修订。历史不铺满默认详情。

图已经表达清楚的上下游，不在旁边再完整复述一遍。状态在最需要它的位置有一处主要表达；目录、节点、详情和页首不重复展示同一组三轴条。

DA 的正常、失败、恢复及旧能力保护沿同一拓扑逐步阅读；其他项目也可定义有目的的阅读路径。路径是视图，不复制节点和业务关系，不改变实现状态。

### 修订

默认按项目或当前对象显示有意义的修订，不显示所有 Git commit 的巨型时间线。每次修订提供范围、before/after、触发依据、原因、实现变化、影响和未变保证。图中变化可作为另一投影，包含删除对象和旧关系；范围以外的当前对象明确只是上下文。

并存科学模型使用 variant；同一对象随时间改变使用 revision；来源借鉴与替代使用 lineage。现有科学模型比较、谱系及证据投影继续可达，只是归入适合的当前对象或修订上下文，不另建重复的主导航。

### 检查

检查页把机械矛盾、证据不足和需要专业判断的问题集中到受影响对象，允许按冻结范围查看。每个项目显示真正存在的问题，点击即可回到具体关系、机制、来源或要求；不使用总体架构质量分。

“没有发现结构矛盾”只说明所运行规则的结果。它不等于架构完整、算法正确、成品通过或 Freeze 获得批准。规则版本与检查对象必须可查。

## 5. 手机重新组织阅读

手机默认先给当前项目、阅读路径与对象列表。用户按步骤进入某个组件或关系，阅读机制，再按需打开实现、证据与历史。返回时恢复原路径、步骤和选择；全图作为按需打开的关系视图，不用一张很高的缩小 SVG 占据所有内容之前的位置。

机制在窄屏采用逐步序列、状态列表或可滚动的局部公式，不裁掉关键参与者和转移条件。前后比较改为带清楚版本标识的纵向对照；产品页的结构示意先呈现被选对象，再按需查看完整页面关系。原始代码和公式确需局部横向滚动时，范围限制在该内容区域。

桌面与手机引用同一实体、关系和证据身份。触屏主操作具有充分命中面积，键盘可进入同等内容；焦点、关闭、返回与浏览器历史不因断点切换丢失。

## 6. 架构设计与 Freeze 合同

Chat 按用户能力与边界 → 核心对象 → 组件责任 → 关系/载荷/消费者 → 关键机制 → 正常/失败/恢复 → 实现责任 → 验证方法 → open issues 的顺序完善架构。这个顺序帮助找到空白，不要求每个项目创建相同数量的章节、节点或字段。

已接受且处于冻结范围的关键组件必须有可理解机制，或者有具名提供方、输入输出、失败语义和验证责任的外部契约。未定算法可以保留 `unresolved`；如果冻结范围依赖它决定关键行为，就阻止该范围进入实施，而不是留给 Codex 即兴发明。

| 可以机械检查 | 仍需明确的人或专业判断 |
|---|---|
| 端点/身份/引用是否存在，信息流是否有载荷和消费者 | 是否漏掉整个用户场景或真正消费者 |
| 关键组件是否缺机制或外部契约 | 机制是否足以成立，black box 是否合理 |
| 声称实现是否有可定位来源 | 实现行为是否符合设计含义 |
| 声称验证是否有当前对象的相应证据 | 证据是否充分，科学与产品结论是否成立 |
| 修订是否有触发、原因、影响和保留边界 | 取舍是否正确，影响是否被低估 |
| 证据依赖是否变化，来源是否出现 drift | 变化是否改变行为，哪些结论仍可沿用 |

Freeze 保存范围、接受决定、未决项及其边界、机制与实现责任、验证计划和不可变输入摘要。设计冻结允许实现尚未开始；它不能把尚未决定的关键行为伪装成实现细节，也不能用设计审阅代替运行验收。详细执行合同由 [ARCHITECTURE_DESIGN_AND_FREEZE.md](ARCHITECTURE_DESIGN_AND_FREEZE.md)规定。

## 7. 修订、返修与双向对齐

Git commit 标识材料快照，architecture revision 标识有意义的设计截面及改变原因。一次修订可以引用多个源码提交，一个源码提交也可能只更新定位或拼写。修订不通过每次提交自动生成。

语义差异以稳定身份比较实体定义、关系契约、机制、假设、要求、符号含义与绑定。布局、主题、选择、折叠和生成时间不进入语义差异。关系删除时仍使用旧关系寻找受影响消费者；传播结果是待核对范围，不自动成为已证实的行为影响。

设计领先代码时，显示新机制和关系尚无实现、旧入口仍在运行的具体位置。代码领先设计时，显示已绑定来源及关键依赖的变化，让作者确认语义是否改变。单纯时间较新、路径可读或内容指纹相同，都不足以说明对齐。

旧路线被撤销后保留身份、触发证据与影响范围；替代路线仍可处于未定。纠正通过新的记录说明旧结论哪里不成立；回滚也产生新修订并重新判断来源与证据，不能抹去中间历史。详细规范见 [VERSION_EVOLUTION_AND_DRIFT.md](VERSION_EVOLUTION_AND_DRIFT.md)。

## 9. 视觉系统和可访问性

使用新的 Asteria 视觉系统：克制的中性面、清楚的文字层级、紧凑但不拥挤的导航、可读的系统节点与关系。图、对象详情和局部历史各自有空间；不以无意义渐变、几何装饰、大状态卡和密集 badge 填补留白。

浅色与深色各自定义背景、层级面、边、选中/焦点、代码、公式、差异、证据和开放问题的语义 token。深色主题需要单独调整层级和文字/边线对比，不能只做背景反色。公式、代码、删除关系和次级说明在两个主题下都应可读。

节点语法表达对象类型与选择；关系语法表达方向、类型及必要路径差别。状态和 diff 均保留文字、形状或线型渠道，不只依赖颜色。键盘选择与可访问对象列表提供等价操作，焦点可见；弹层有正确焦点进入与返回，减少动态效果时仍能理解路径。

内容质量与整页构图同为交付要求。制作者必须审阅真实默认状态、选中节点/关系、机制、实现、证据、修订、diff 和检查，覆盖四项目、双主题与桌面/手机；执行 KEEP/DELETE/MERGE/RELOCATE/REWRITE，再去除 CSS 连续读可见内容。图已表达的信息不重复，内部编号与研究过程按需下沉。P1 和明显 P2 清零后才交下一轮专业审查，不能自行宣布最终验收通过。细节见 [VISUAL_SYSTEM.md](VISUAL_SYSTEM.md)及 [CONTENT_AND_TASTE_AUDIT.md](CONTENT_AND_TASTE_AUDIT.md)。

## 10. 大图通过投影与局部探索扩展

系统首页展示有意义的能力和边界，不展开整个仓库的函数图。语义对象全部保留在共同快照；默认投影、折叠和局部邻域决定当前画什么，搜索、检查与影响计算仍覆盖被隐藏对象。

大型项目使用以下确定策略：

1. 作者定义系统边界与分组，自动布局只负责排列，不能替作者发明职责。
2. 默认显示可阅读的系统层；展开一组或一个局部邻域时保留当前选择、路径与跨边界连接。
3. 搜索能找到未展开对象，并以可解释路径进入其上下文；筛选不删除原对象。
4. 源码索引在选定机制附近显示定义、调用与消费者，不进入首页制造高密度毛线图。
5. 布局按投影输入摘要缓存；大型计算离开交互主线程；图形只渲染需要的可见对象，但模型查询不因此截断。
6. 历史比较使用范围内旧/新对象与必要边界；删除对象仍有可选择的历史位置。

图交互复用 React Flow，布局复用 ELK，代码着色与数学渲染复用 Shiki 和 KaTeX；来源索引、语法差异及其他能力按 [OPEN_SOURCE_ADOPTION.md](OPEN_SOURCE_ADOPTION.md) 的选择逐步接入。Asteria 自己负责语义、来源合同、投影意图、证据有效性和变化解释，避免同时引入多套通用运行图引擎。

大图能力必须用真实和明确标记的合成数据测量，报告完整数据规模、可见投影规模、布局与交互条件。本轮 reference 规模不构成千节点可用性的证明。

## 11. 渐进交付顺序

| 阶段 | 先完成什么 | 可以据此交付的范围 |
|---|---|---|
| 兼容与共同模型 | 固定现有基线、保留 1.x/2.0 材料、版本化 schema 和迁移 | 旧科学项目完整读取，新实体种类可表达 |
| 可复现作者入口 | 原文件选择器、结构登记、固定来源、唯一快照及报告 | 手工策展项目可以稳定生成阅读包 |
| 当前系统与四类机制 | 三主导航、同图路径、选择/关系、专用 renderer、双主题/手机 | 四项目当前系统可自然阅读，合法空状态成立 |
| 来源与演进闭环 | 实际来源解析、范围化 diff、因果修订、证据适用性、双向 drift | 组件能追到真实实现及为什么变化 |
| 设计冻结与规模验证 | 范围检查、专业判断记录、迁移/恢复、复杂图和全产品验收 | 明确范围内可交给 Codex 的设计包与可持续维护流程 |

每阶段交付完整纵向阅读路径，而不是先堆所有字段再补界面。具体工作、负例、保护项与退出条件见 [CODEX_HANDOFF_CONTRACT.md](CODEX_HANDOFF_CONTRACT.md)。

## 12. 原型与正式产品之间的界线

本轮原型使用固定来源研究数据，在一份静态候选里演示项目切换、系统选择、关系、机制、来源、证据、局部修订、检查和主题。它包含实际模型计算，但不是正式 schema、通用仓库导入器或所有来源语言的索引器。浏览器检查负责说明哪些演示状态实际可用，不能从本规格反向推断其已经实现。

正式阶段仍须补齐确定性作者编译、深层 schema 校验、真实来源解析/指纹与歧义、旧格式迁移、完整语义 diff、依赖适用性、不可变冻结摘要和版本恢复。原型中的人工整理因果关系与依赖是解释样例，不是已经学会自动发现因果的系统；静态检查无错误也不构成 Architecture Freeze。

最危险的产品风险是来源与架构被维护成两份会逐渐分离的内容，以及一个有效链接被误认为当前实现已对齐。应持续用四项目的真实变化检验维护成本和误判，优先修好来源身份、因果范围与阅读路径，再扩大自动索引覆盖。
