# Codex 交接合同

本合同在最终裁决采纳本候选、并给出正式 Asteria 实施任务后执行。本轮研究不修改 `YuukiAS/Asteria`，不授权发布或改动四个来源项目。未来实施沿现有 Asteria 继续演进，按本合同完成已确定的行为；不再选择第二套产品或平行 Ledger。

产品结论见 [ASTERIA_NEXT_CANONICAL_SPEC.md](ASTERIA_NEXT_CANONICAL_SPEC.md)，数据与来源分别以 [SEMANTIC_MODEL.md](SEMANTIC_MODEL.md) 和 [SOURCE_BINDING_AND_EVIDENCE.md](SOURCE_BINDING_AND_EVIDENCE.md) 为准。原型提供可审查的阅读与交互参照，其缩减数据结构不是正式生产格式。

## 1. 已经确定的行为

Codex 可以自行决定符合合同的模块划分、内部函数名、缓存实现和小范围样式细节。下列产品及语义行为已经确定，不能在实施中悄悄改写。

| 已冻结的选择 | 实施约束 |
|---|---|
| 产品继续叫 Asteria | 在现有宿主扩展；保留既有科学语义与旧数据兼容，不建另一个项目数据库 |
| 单一 canonical model | 共同实体/符号/关系/变体/视图，扩展锚点、绑定、修订；机制、证据、问题等采用类型化能力面 |
| 原文件为作者入口 | `.asteria/project.yaml` 登记身份与关系并选择原文；每个规范性字段只有一个作者来源 |
| 当前优先 | 三主导航为当前架构、修订、检查；机制、实现、证据和局部历史跟随当前选择 |
| 关系可以深入 | 传输关系有载荷、消费者与触发；已有实现需有真实消费位置；设计消费者不伪造函数 |
| 纯设计和未定算法合法 | 空绑定合法；未决定的关键行为按影响范围阻止实施，不由 Codex 填空 |
| 三类判断分开 | 设计状态、实现定位、证据适用性分别保存；不能合成进度分或自动“已验证” |
| 历史不可被当前覆盖 | meaningful revision、稳定身份、局部范围、触发/原因/影响/保留条件；纠正与回滚追加记录 |
| 一套模型、多种表达 | procedure/state/sequence/formula/numerical/artifact 等 renderer 按内容工作，不按项目名写四套业务分支 |
| 桌面与手机分别组织 | 桌面图加 inspector；手机路径和对象先行，关系图按需；双主题同样可读 |
| 复用成熟能力 | 图交互/布局/公式/代码着色及来源索引按 [OPEN_SOURCE_ADOPTION.md](OPEN_SOURCE_ADOPTION.md) 采用；不同时建立多套通用图引擎 |

若实际源码暴露冻结设计中的矛盾，Codex 记录具体来源、受影响行为和最小修订建议，并继续完成不受影响的工作。科学算法、产品边界、责任迁移和证据足够与否交回相应设计负责人判断；不能以“实现方便”替换为另一种行为。

## 3. 分阶段实施与退出条件

各阶段是技术完成条件，不要求每个小步骤重新等待用户确认。正式任务已经授权的范围内可连续推进；范围外的科学或产品决定保持显式缺口。

### 阶段一：共同模型和无损兼容

在现有核心旁建立版本化 Next schema 和迁移入口；保留实体、符号、关系、变体身份。去除软件/Artifact 被迫填写科研层级的条件，保留科研对象原有属性。新增锚点和修订，将已有 bridge binding 迁入规范化绑定表。

可判别能力面必须真正校验，不能只扩大 TypeScript 类型后继续强转。未知种类/能力面不能静默获得有效身份；旧格式未能解释的内容进入有标识的兼容载荷，且不参与新的验证结论。旧的 `TESTED` 或 `supported` 只能保留其原始声明，不能直接提升为当前证据有效。

**退出条件：** 原 1.x 数据继续完成既有 round-trip；2.0 项目迁移后科学定义、公式/符号绑定、关系、变体和来源不丢失；DA 空绑定、CAT 未定算法和 Tutorial 页面对象均可通过适用的格式校验。实际读取层只选择一个语义快照供所有视图使用。

### 阶段二：确定性作者入口和来源编译

实现原 Markdown/结构登记的选择器、字段来源清单、固定提交读取与可重复快照编译。新作者格式示例只是模板，不能假称 Mica 等外部仓库已有这些文件。四参考项目的描述登记可保存在 Asteria 参考材料中，引用原项目；未经另行任务授权，不向源仓库写入 `.asteria` 文件。

解析来源时生成不可变锚点与派生定位结果，至少支持确定性文档节块、已声明代码结构选择器，以及固定候选的页/对象定位。引用可打开只证明入口存在；函数绑定还需限定名/结构选择器与实际匹配指纹。索引器提供候选定义、引用和消费点，动态调用或语言不支持时明确范围。

不得在每次编译时调用模型重新解释正文并悄悄改变结构。不能唯一确定的实体、关系或选择器进入待作者确认的建议；接受后才形成结构登记。同一字段多个来源冲突必须可见。

**退出条件：** 相同作者输入与解析规则生成相同语义摘要；改布局/生成时间不改摘要；私有来源不可访问得到 `unavailable`；同名函数歧义得到 `ambiguous`；文件存在但目标函数消失不算成功；空绑定仍正常工作。

### 阶段三：当前系统的完整阅读路径

接入三个主导航、系统投影、目录/搜索、节点与关系选择、局部上下游和路径步骤。路径切换保持同一拓扑与稳定身份；图与 inspector 通过空间分配共存，不让面板遮住当前关键节点。节点、边标签、边命中区域和等价列表均可操作。

机制 renderer 使用共同类型读取 procedure、sequence、state、formula、numerical 和产物结构；未知内容以清楚的正文/来源形式保留，不套入错误状态机。Mica 的事件与状态、CAT 的公式与算法、Tutorial 的页对象能自然阅读，DA 无实现时有准确且简短的空状态。

手机默认路径与对象阅读，选择后进入详情，返回保留步骤；图按需展开。实现独立浅色/深色 token、可见焦点、状态非颜色编码、缩减动态效果及必要的可访问文字。主题/窗口变化不能改变对象、证据或状态含义。

**退出条件：** 四项目的“当前系统 → 选择对象或关系 → 机制 → 真实来源/合法空状态 → 证据范围”路径均可完成；同一对象在目录、图、详情与搜索的身份一致；主流程不依赖 hover、颜色或桌面宽度。

### 阶段四：修订、语义 diff 与证据适用性

比较器读取两份真实快照，覆盖模型约定的语义对象及字段。布局、主题、显示缓存和观察时间排除；修改符号含义、机制前提、关系载荷或消费者需要被识别。删除对象及关系保留在比较结果，局部范围之外的当前背景不能被标成“确认未变”。

revision 保存触发、理由、范围、影响与未变保证，引用证据及决定。真实历史重构用 `source_reconstruction`，只有具备原接受依据的冻结记录才用 `frozen`。父修订与范围对象均校验，摘要按正式模型合同计算，不填写占位哈希。

证据结果保持不可变；当前适用性根据对象、要求、方法、代码、环境与上下文依赖重新计算。已知依赖变化产生失效或复验范围，未知依赖保持待核对。没有依赖清单不能直接推导“可以保留”。影响传播使用旧/新关系并集并遵守关系类型/影响合同，避免删除关系恰好抹掉旧消费者。

**退出条件：** Mica 的真实局部修订、CAT 的参考更新与撤销路线、Tutorial 的历史局部修复均有准确 before/after 和范围；设计演示不生成虚构执行结果；Tutorial 四种主要改动能解释哪些证据重取、哪些有条件复用。

### 阶段五：设计检查、Freeze 与双向 drift

统一检查器产出有稳定定位的机械 findings，支持导出给 Chat/Codex。检查器直接读取 canonical model，不能用面板是否可见、文字是否包含某个词来决定结构有效性。

Freeze 是一份范围明确、可复现的设计合同。它记录接受依据、关键机制、实现责任、验证方法、未决问题及其阻塞边界。DA 可以设计冻结而无代码；CAT 的未定关键生产算法阻止相关范围冻结，但不应阻止无关稳定数值内核的文档整理。专业判断保存判断者、对象、依据及结论，机械无错误不自动授予冻结。

来源刷新产生新观察而不覆盖设计。设计领先代码时报告尚未接入的机制与关系；代码领先设计时报告实际变动及受影响对象，等待语义确认。重绑定、纠正、撤销和回滚都保留原锚点及修订。

**退出条件：** 约定负例能够产生有解释的缺口，正常纯设计不会因无代码误报；已冻结记录可重建并校验输入摘要；来源不可访问、定位变化、行为变化和证据不足互不混淆。

### 阶段六：规模、迁移恢复与整产品验收

完成层级投影、折叠、跨边界关系、搜索未展开对象和局部实现图。布局和索引按输入摘要缓存，大型计算不阻塞基本阅读。使用固定的真实参考图与明确标记的合成大型图记录导入、布局、搜索、选择、diff 和内存条件；报告完整图与可见投影规模，不以只渲染少量节点宣称完整大图无成本。

执行数据升级/回滚演练，再完成四项目、双主题、桌面/手机、当前/diff/机制/实现/证据/检查的真实浏览器检查。执行内容存在性、人话、无 CSS 连续阅读与 whole-product taste 审查。制作者修完 P1 和明显 P2，保存证据与未解决限制后交独立审阅。

**退出条件：** 已约定范围的旧能力和新阅读任务均有证据；迁移失败与回滚不会丢数据或重写历史；报告不把机械测试通过写成科学正确、专业验收或最终裁决通过。发布只属于另有明确范围的部署任务，继续遵守正式仓库已有入口约定。

## 4. 必须覆盖的语义负例

这些检查用于保护关键语义，不要求为每个低影响样式改动新增测试。先补核心不变量与真实故障回路，再按变化范围运行适用回归。

| 输入或操作 | 必须观察到的结果 | 它保护什么 |
|---|---|---|
| 已接受的关键组件没有机制，也没有外部契约 | 在其冻结范围产生明确缺口 | 不让 Codex 临时发明关键行为 |
| 外部契约没有失败语义或责任提供方 | 保留未闭合项，不能用 black box 绕过设计 | black box 的合理边界 |
| 信息流无 payload、consumer，或消费者不属于目标责任 | 定位到关系及缺失字段 | 箭头真正可解释 |
| `contains` 或科学参数关系没有消息 payload | 不因不适用而报错 | 领域语义不会被统一表单破坏 |
| DA 完整设计的 `bindings={}` | 可导入、可读、实现为空；不自动通过运行验收 | design-only 合法 |
| linked 实现仅指向存在的文件，目标函数缺失 | 文件粒度或失联，不能标为函数已核对 | 来源粒度真实 |
| 两个同名函数或一个 selector 命中多处 | 显示歧义与候选，不静默选第一处 | 稳定绑定 |
| 来源无权限或暂时不可访问 | `unavailable`，保留上次固定来源 | 不误报删除 |
| 改节点坐标、主题或折叠 | 不产生语义 diff | 比较不被外观噪声淹没 |
| 改符号含义、公式前提或关系消费者，标签不变 | 产生相应语义 diff | 名称相同不等于机制未变 |
| 删除旧消费者关系后计算影响 | 旧消费者仍在待核对范围，循环不会无限传播 | 返修不会漏查断开的下游 |
| 局部历史只重构一个组件 | 其他对象显示为当前背景，不标确认未变 | 历史范围诚实 |
| 用旧候选通过证据，或只改时间戳 | 当前适用性仍按依赖判断，不能恢复有效 | 不重复使用旧通过结论 |
| 所有已知依赖未变化，但关键依赖不完整 | 显示待核对，不直接判可复用 | 不以缺信息当无影响 |
| 页码不变但对象内容已换，或页面重排 | 旧锚点保持旧候选；新定位与叙事证据重建 | Tutorial 反馈不接错页 |
| 课程要求变了、PDF 字节没变 | 受该要求约束的结论需要重新判断 | Artifact authority drift |
| CAT reference 有正确性测试但可靠性未满足 | 两种结论同时保留 | 不把测试链接变成科学金标准 |
| 旧路线被反例撤销，替代算法仍未定 | 保留旧路线与反证，生产模块继续 open | 不从撤销推导替代完成 |
| correction/rollback | 追加新修订，旧证据和原因可追溯 | 历史不可被清空 |
| 不受信任的链接、Markdown 或对象标签 | 按安全渲染合同处理，不执行嵌入脚本或读取越界文件 | 原材料只是内容 |

冻结的科学内容不作为测试修复的工具。若现有测试与正确科学定义矛盾，保留原结果、定位冲突并提出修订；不能删去反例、降低误差要求、改私有数据、替换模型或编辑结果让测试变绿。

## 5. 必须保留的旧能力

### 1.x 数据与恢复

现有 `test:legacy-roundtrip` 覆盖旧标题、模型版本、当前变体、富文本数学、符号表、分组、边样式、视口和叙事提纲。Next 保留这些原始内容及可恢复性；迁移后的新增语义字段不回写破坏原文件。历史 UI 仍留在 archive，不重新成为 active 产品。[旧格式回归定义][asteria-legacy]

保存/恢复继续区分产品会话与项目权威。浏览器本地状态只保存选择、视图等会话或明确的未提交草稿；不能覆盖 Git 当前快照。导入覆盖、版本不支持或草稿基线变化需要显示具体差异，提供保留和导出路径，而不是丢弃数据或最后保存者覆盖。

### 2.0 科学语义

Original TRACE 与 CAT-TRACE 的实体、符号、约束、公式、变体、模型比较、谱系和证据仍能追到原身份。当前含变体名的 ID 不自动去前缀合并；不根据标题相同判定同一科学对象。原有科学校验继续运行，新增软件或 Artifact 类型不能让其失效。

将旧预写 diff 替换为真实比较时，保留有价值的历史作者解释；将证据边计数替换为依赖判断时，保留旧结果与原声明。迁移可以降低一个过强的“已验证”显示到“旧声明待核对”，必须解释原因，不能偷偷丢掉来源。

### 四个参考项目的事实

DA 不增加假实现；Mica 不把未来适配层画成现有运行结构；CAT 保留反例、未定生产模块和可靠性限制；Tutorial 的页面正例、当前要求漂移、历史局部修复与验证器缺陷分开。私有材料仅使用本候选允许的脱敏概念和固定入口，不复制源码、结果表、日志或原始课件图片到公共产物。[永久参考合同](FOUR_REFERENCE_PROJECTS.md)

## 6. 迁移、摘要与 rollback

迁移采用“读取旧输入 → 生成新快照与报告 → 校验 → 明确选择新读取路径”，保持原始输入不变。格式版本、迁移器版本、输入摘要、丢失/未知字段以及所有身份对应均记录。多次迁移相同输入应产生相同语义结果；不能累积新 ID 或重复实体。

正式 schema 的摘要规则按 [SEMANTIC_MODEL.md](SEMANTIC_MODEL.md) 实现：语义摘要排除布局与修订表自身；来源清单覆盖实际作者输入；当前修订记录去掉摘要字段后参与来源清单。固定 Git 提交由读取观察补充，修订作者不手填尚不存在的自身提交。所有摘要来自真实字节或约定规范化内容，禁止占位值。

回滚时切换到保留的旧读取路径或旧发布版本，原始项目仍可使用。新格式若不能被旧版理解，应明确保留可导出的新数据，不尝试无损性未证实的降级覆盖。已写入的新设计决定和历史记录保留；回滚产品代码不自动回滚设计结论。

缓存可删除后重建；未提交草稿另行保存基线摘要和修改，不与缓存一起清空。禁止以清空 Dexie/localStorage、删除数据库或重新初始化项目作为正常迁移手段。确需修复损坏数据时，先保存可恢复副本和范围说明。

## 7. 原型哪些可借用，哪些必须正式实现

| 本轮参考内容 | 可作为实施输入 | 正式阶段仍须完成 |
|---|---|---|
| 四项目策展数据与阅读路径 | 对象范围、术语、真实锚点、关系及机制表达 | 由作者格式和来源编译生成；每字段可追到权威，更新无需改四份网站 |
| React Flow + ELK 图与详情布局 | 选择、关系命中、同图路径、图与 inspector 的构图方向 | 接入现有产品会话、层级/大图、键盘与焦点、真实数据变化 |
| 简化 `model-core` | 纯计算、旧新关系并集、结构缺口的思路 | 完整 schema 与类型合同；生产错误处理；所有语义对象和依赖范围 |
| 当前 before/after 演示 | 局部比较、删除对象、why changed 的阅读顺序 | 正式快照摘要、父修订、完整范围及不可变冻结记录 |
| 固定源码入口与已整理说明 | 来源身份和范围可核对 | 通用解析、指纹、歧义、语言支持、绑定迁移和双向 drift |
| Evidence/impact 演示 | 变化依赖怎样向用户解释 | 完整证据 subject/dependency、未知状态、适用性重算与复用理由 |
| 完整性检查入口 | 缺口集中呈现与跳回对象 | 按机制/关系/冻结范围校验；结构结论与专业判断分开 |
| 双主题和手机状态 | 视觉与阅读顺序参照 | 正式产品所有 primary screens 的真实渲染与可访问性检查 |

原型关系类型、修订字段和证据 subjects 是为演示压缩的结构，不能覆盖正式模型中的 `TransferContract`、`parentIds`、`EvidenceSubject` 和依赖摘要。本轮检查器的无错误结果不能替代生产 Freeze。原型依赖列表、界面截图和纯函数测试也不能证明正式数据迁移或真实来源抓取已经完成。

## 8. 测试与制作者验收

模型与迁移测试围绕上面的不变量、反例和旧数据运行。源码解析使用固定 fixture，包含成功、歧义、文件存在但对象消失、权限不可用和重命名；实际私有项目只在有权访问的环境核对。差异与证据测试使用真实局部历史和明确标记的合成负例，不制造伪运行记录。

浏览器测试以用户任务为单位：四项目切换；当前系统阅读；节点与关系；正常/失败/恢复/旧能力路径；机制/实现/证据；修订与图中 diff；检查跳回对象；light/dark；手机返回；键盘和焦点。不要只断言组件存在或截一张首页图。

制作者检查真实渲染中的碰撞、裁切、滚动、面板平衡、选中/hover/focus、密度、首眼层级和重复内容。内容审查覆盖默认、详情、历史、检查、四项目、双主题和手机，先删无信息增量的元素，再改文字；去掉 CSS 后仍应是自然连贯的技术内容。

改动只影响某个模块时运行相关回归；完整迁移与发布候选阶段运行仓库要求的全套 gate。旧 UI 断言因明确产品改动需要更新时，记录新旧行为与保护证据，不删除失效断言后宣称无回归。性能仅报告实际测量范围，科学结果仅引用原有或实际新执行的证据。

P1 与明显 P2 清零是交给下一轮 Work 的制作者门槛。它不是最终专业或用户验收。交付时保留实际失败、未覆盖范围、环境限制及最危险的剩余问题，不以自评分替代判断。

## 9. 正式阶段的交付记录

每个可审查候选交付源码提交、可复现构建入口、schema/迁移版本、输入与输出清单、变化说明、适用测试与实际结果、浏览器截图/交互记录、内容和视觉审查、数据恢复演练及尚未完成的范围。四参考项目的固定来源、访问边界与来源读取日期一并保留。

变更说明先解释解决哪个用户问题、机制如何改变、哪些旧能力保留，再列必要技术与验证范围。未运行的检查明确写未运行；测试定义、运行结果和专业判断分别列清。已授权范围内的远端写入与部署遵守正式任务及仓库约定，本研究合同不另行授予这些动作。

验收者最终要能独立回答：从任何一个当前组件或产物对象，能否找到机制、真实来源、适用证据和一次变化的因果；无实现、无唯一算法、旧结论被纠正时，产品是否仍清楚可信。实现只有在这些阅读任务成立且旧数据可恢复后，才达到本合同的交付范围。
