## 内容先做存在性判断

[可见内容裁决表](qa/rendered-content.tsv) 记录 68 个重要内容区块的 KEEP、DELETE、MERGE、RELOCATE、REWRITE。表格以真实渲染为依据，覆盖默认页、组件、关系、机制、实现、证据、历史、diff、检查、四项目和手机；没有把静态字符串扫描当作审查。

主要取舍如下。

**首页保留系统与路径。** 节点只写名称和语义图标，关系保留可选择的短标签。职责、载荷、消费者、源码和证据进入选中详情。首页没有再加一组卡片复述整张图，也没有为了展示设计 / 实现 / 证据三轴而在每个节点铺开所有字段。版本或设计身份在页头承担主要表达位置。

**同一状态只保留主要说明。** Tutorial 候选对象改为说明文件身份和有序页面；第 35、37 页的过时课程事实在问题区表达。CAT 未定积分模块的职责只说明数学贡献，误差、导数、成本和适用范围的缺口集中在开放问题。DA 修订中相同的摘要与理由合并，空的相邻关系标题删除。

**保留有判断价值的边界。** DA 的实现为空、CAT 尚无冻结生产算法、Mica 本地检查不等于当前线上兼容、Tutorial 局部修复不等于整套通过，都影响读者的判断，必须保留。这些条件没有扩张成满页的 reassurance 或巨大状态卡。

**来源下沉，但不抹掉身份。** 具体 finding、实现、证据和修订中保留原文件名与固定提交。`03_THREE_FAMILY_EXECUTION.md` 等名字在这里属于深入追溯所需的精确来源：前面已经用人话说明了问题、依据和修复范围，读者不必先理解内部编号才能操作。它们不作为首页标题或流程名，因此本轮裁决为 KEEP。将来来源变多时可以添加语义显示名，但不以可选的标题润色重开本候选。

**手机重新排阅读顺序。** 当前架构以路径和动作在前，对象和全图按需打开。手机 diff 已从缩小整张桌面图改成变化对象清单，点击后读前后内容；完整关系图需要主动展开。进入详情后返回入口在首屏，返回时恢复原来的路径位置。

## 去掉视觉层级后，正文是否仍然成立

读稿先从每个实际可见状态按 DOM 顺序抽取正文，再去掉排版连续阅读，并回看对应截图。CSS 隐藏的其他断点副本、SVG 的辅助文案和未展开下拉框中的全部选项，不当作当前读者正文。额外执行的字面 CSS 移除会暴露响应式备份节点，该调试结果保留在记录里，但不能据此把隐藏副本误判为产品重复。

这次读稿检查的是句子在该位置有没有工作可做，而不是命中多少禁词。机制中的动作和条件应能独立读懂；事实、实现状态和证据范围应能分清；历史应说明触发和变化，而不是说明“本产品可以追溯”。

实际返修包括删除“有意义的修订”及其自我定义说明，合并 DA 的重复理由，改写产物对象套用的“已有源码”空状态，以及缩窄结构检查的结论。技术名称只在需要精确定位时保留。Mica 的守护条件、CAT 的数学目标和 Tutorial 的页面位置没有为了句子更短而被删掉。

最终正文以对象责任、行为顺序、约束、证据和变化原因为主，没有加入研究评分、制作任务编号或解释原型如何实现的段落。代码节选、测试名、源文件名属于追溯材料，不承担产品宣传。

## 完整基线后的事实与图形纠正

最后事实核对发现，`recorded_result` 不一定是运行结果。Tutorial 的历史记录包含专业审阅，通用类型文案因此改为“已有结果记录”。在 Tutorial 历史页与 CAT 参考算法各自的 light / dark、桌面 / 手机状态中实际复验，共 8 态，具体证据范围仍由各条正文说明。

Mica 的历史对照也收紧到固定源码能支持的内容。0.1.6 观察窗口是 3200ms，0.1.7 是 4200ms；旧选择动作由 `handlePotentialConnectorSignal → detectSignal` 消费，旧普通输入路径由 `handlePotentialMentionEvent → beginLifecycle` 消费，并受连接器上下文条件约束。旧发送互斥要求两个条件同时成立；当前任一发送状态即可阻止新建。两者都不能据此推断已有外观层立即移除。历史中未完整重建的关系源码锚点从比较两侧排除，三对已核读的函数仍保留。旧 3200ms 核对来自模型语义值，未声称摘要界面显示了该数值。

事实纠正后的 [28 态记录](qa/audit-final-delta.json) 包含 4 态当前机制和 16 态历史总览、关系选择及前后对照，另有上述 8 态证据页面，共 27 项检查。截图逐态查看，正文按实际可见顺序阅读。Mica 新出现的消费者差异还暴露了一项图形缺口：修改关系在未选中时仍是普通灰线。最终修复用修改色、1.8px 线宽和可见“修改”文字表达，避免只依赖颜色。

[最终 6 态视觉复验](qa/audit-final-diff-visual.json) 实际检查双主题桌面总览、关系选择和手机主动展开图；7 项检查包括标签碰撞、非端点穿线、横向溢出及事实模型 hash 相同。6 张截图逐一核读，未发现新的明显 P2。手机主要阅读入口仍是变化对象清单，主动展开的全图用于空间定位并提供缩放。

## 整页、主题与可访问性判断

桌面页面把面积留给系统图；选择后图仍保留上下文，右侧内容随任务改变。机制使用顺序、条件、公式或页面对象表达，没有强迫四个项目采用同一组内容卡片。修订默认读具体变化，未把巨型时间线放到首页。空实现和没有局部历史的对象保留适当留白。

light 与 dark 分别使用画布、侧栏、详情表面、代码底色和状态色。两主题的差异不止背景反色。新增、撤销和修改同时有文字，选中和键盘焦点也有各自的形态。浅色普通关系线经返修加深；代码颜色的实际计算值保存在主题记录，不能只因 CSS 中写了 token 就宣称已接通。

手机主要操作的命中高度是 44px；顶部三项导航的文字按钮宽度为 37px，彼此保留间隔。本候选的视觉规格承诺的是命中高度，本轮记录实际宽高，没有把它扩大成所有目标均为 44 × 44px。节点 Enter / Space、来源弹窗焦点范围和回返，以及布局稳定后的节点焦点与 Tab 顺序都有实际检查。瞬时日志中有一次布局过程的空焦点字段，因此额外核对了 DA 和 Tutorial 的首尾节点，结果见 [稳定后的节点焦点](qa/audit-r6-node-focus-followup.json)。

## 结论范围与仍需验证的事

记录的 P1 与明显 P2 已按“完整基线 + 两次定向复验”闭环，范围是这四个 reference、上述 Chromium 和两个视口、实际走过的状态及操作。最终核对入口明确列出三个文件身份。

交付保留 r6、事实 delta 和最终视觉 delta 的全部截图，以及旧轮中被问题记录明确引用的 7 张缺陷示例。538 张未被最终文档引用的旧巡检图移出候选；[裁剪清单](qa/screenshot-curation.json) 保存原路径、hash、大小和原因。旧 JSON 仍保留原始观察，其中已移出的截图路径只作为历史巡检索引，不作为交付证据入口。没有悄悄删掉问题表引用的缺陷证据。

这份原型没有实施正式 Asteria 的仓库导入、持续索引和变更后证据失效流水线，也没有验证任意规模的真实项目。手机检查是浏览器视口检查，未替代真实设备、Safari、Firefox 或屏幕阅读器验收。Mica 当前线上 DOM、DA 恢复接线、CAT 科研计算和 Tutorial 产品返修，都继续遵守各自明确的证据边界。

最需要防止的后续退化，是让“引用完整”再次被理解为“事实正确”，或让产品缺陷和架构设计冻结混为一项状态。Tutorial 当前说明已明确：验收回路的设计可以单独整理，课件和验证器的未修问题仍阻止产品验收。
