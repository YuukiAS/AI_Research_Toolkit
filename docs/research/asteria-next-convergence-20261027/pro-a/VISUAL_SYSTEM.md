# Asteria 的视觉与阅读系统

这套候选以当前系统为起点。桌面把空间留给可读的拓扑，选择对象后再出现详情；手机从任务路径进入对象。机制、源码、公式和产品页面分别采用适合自身的表达，仍共享选择、来源、修订和证据身份。浅色与深色使用两套语义颜色，并在实际页面中分别检查。

视觉方案没有沿用任一历史原型的页面文件或样式。保留了 R2 GPT-6 的同图路径与直接选择，采用上轮候选的逐层追查方法，再依据 Work 的内容存在性审查重排整页。具体能力取舍见[裁决矩阵](CONVERGENCE_DECISION_MATRIX.md)，实际缺陷、修复和截图见[制作方审查](CONTENT_AND_TASTE_AUDIT.md)。

## 先确定页面需要什么

默认页面只承担三件事：识别当前项目，看见系统如何连接，选择一条阅读路径或一个对象。项目描述压到一行；来源、固定提交、研究过程、完整检查规则和旧方案不占默认画布。初始没有对象详情，也没有总体完成率、三轴状态墙或解释本产品价值的欢迎卡。

组件名称回答它是什么，机制回答它如何工作。关系标签只保留可区分的交接名，选中才展示载荷与消费点。图里已经清楚的方向无需在正文完整重述；局部关系入口用于进一步导航。缺少历史时只显示简短事实，不生成空时间线。设计没有执行实现时，空状态出现在用户主动打开“实现”之后。

以上决定直接采用 Work 的 [EDITORIAL_AND_CURATION_AUDIT](https://github.com/YuukiAS/AI_Research_Toolkit/blob/ce8442b799e0096b79367da701289255bfa23bd3/docs/research/complex-system-showcase-20261026/r2/editorial-audit/EDITORIAL_AND_CURATION_AUDIT.md) 和 [PLUGIN_REALITY_CHECK](https://github.com/YuukiAS/AI_Research_Toolkit/blob/ce8442b799e0096b79367da701289255bfa23bd3/docs/research/complex-system-showcase-20261026/r2/editorial-audit/PLUGIN_REALITY_CHECK.md)。本轮没有把尚在 TODO 的自动策展工具写成已具备的能力。

## 整页构图

| 区域 | 桌面行为 | 窄屏行为 |
|---|---|---|
| 项目与主导航 | 固定宽度的侧栏，当前架构 / 修订 / 检查三个入口 | 项目选择与三个短导航位于页首 |
| 当前系统 | 主体画布；默认没有右侧面板 | 路径步骤和对象列表先出现；关系图按需展开 |
| 对象详情 | 占用实际布局宽度的侧面板；画布重新适应可用空间，不被面板覆盖 | 独立的连续阅读页；顶部返回原路径，恢复先前阅读位置 |
| 路径 | 在同一拓扑切换；底部提供当前步骤与前进/后退 | 直接展示按序步骤，从某一步进入对应对象 |
| 修订 | 前后对照优先；可切换到保持当前位置的变化图 | 前后纵向阅读；“变化对象”先给可点击列表，关系图为次要入口 |
| 检查 | 问题清单与当前冻结范围并列 | 先读问题，再选择范围并看需要回答的判断 |

原型在 1440 像素宽度使用 208 像素侧栏、111 像素顶部区、365 像素对象面板。它们是本候选实际构图尺寸，不是正式产品必须永久锁死的设备假设。800 像素以下切换阅读结构；801–1200 像素缩紧目录与详情，但仍保留完整画布区域。布局和断点的实际实现见 [style.css](prototype/src/style.css)。

画布不使用点阵、装饰几何或背景渐变。留白分隔任务层级，也为选择、边和面板留出空间；没有内容的地方不额外补说明。选中后仍能看见对象周围的协作关系，不用一个巨大状态卡挤走系统。

## 字体、间距与密度

中文使用 Noto Sans CJK SC 2.004 的 Regular 与 Medium 子集，数字与拉丁字母保持相同阅读节奏；代码使用等宽字体。两份字体随自包含原型嵌入，避免浏览器缺少中文字形。字体覆盖常用汉字及本候选全部文本，许可为 OFL-1.1；具体来源与版本见[开源采用](OPEN_SOURCE_ADOPTION.md)。

| 内容 | 本候选的主要规则 |
|---|---|
| 项目标题 | 桌面 23px，手机约 22px；保留项目名自身辨识度 |
| 对象标题 | 20–22px，短标题与正文之间有明确间隔 |
| 机制与详情 | 桌面主要 12–13px，手机主要 13px；行距约 1.8–1.95，不用紧压小字容纳全部字段 |
| 节点 | 184 × 78 的语义节点；14px 名称，少量类型图标；实际屏幕尺寸随视口缩放 |
| 关系 | 简短标签；足够宽的鼠标命中线；选中后在详情阅读完整信息 |
| 源码与位置 | 路径可换行，打开链接保持独立；代码仅在自身区域横向滚动 |
| 区域间距 | 8 / 12 / 16 / 24 / 32 的节奏；不为每个字段增加一圈边框 |

图形中的文字不能因适应窗口而成为主要的手机阅读材料，因此手机有对应的路径和变化对象列表。完整图允许缩放和移动，但不以“用户可以放大”为由保留不可读的默认流程。大型图也应先收敛投影范围，再考虑缩放。

## 颜色与两套主题

下面是实际 token，而非背景反色公式。深色主题降低大面积纯黑的突兀程度，提高文字、代码与图边的可辨识度；明暗下都保留同一意义。

| 语义 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| 画布 | `#f7f8fa` | `#161b25` | 系统上下文与页面底层 |
| 内容面 | `#ffffff` | `#1d2430` | 详情、节点、局部比较 |
| 导航面 | `#f0f2f6` | `#111721` | 稳定的项目与对象入口 |
| 主文字 | `#202939` | `#e3e8f2` | 名称与事实 |
| 次级文字 | `#637086` | `#a1adc1` | 说明与范围限定 |
| 选择 / 主链接 | `#4c50ac` | `#b5b6ff` | 当前选择及可追查位置 |
| 选择底色 | `#eef0fc` | `#30344d` | 不改变节点尺寸的聚焦面 |
| 普通关系线 | `#7e8ca3` | `#677a94` | 有意义的连接，保持可辨识度 |
| 新增 | `#237449` | `#88d7ad` | 与“新增”文字同时出现 |
| 撤销 / 删除 | `#a6414b` | `#f2a3ac` | 与虚线和撤销文字共同出现 |
| 开放条件 / 阻断 | `#86632c` | `#e2bd7c` | 具体问题旁的必要提醒 |

第一轮实际检查发现浅色边线过淡，已加深。状态颜色不替代事实句子：例如 CAT 的生产算法未定在具体阻断位置解释，Mica 的固定来源和本地运行证据分别给出；不会把 amber 或 green 直接解释为整个项目是否通过。实际对比及截图属于[内容和视觉审查](CONTENT_AND_TASTE_AUDIT.md)，不扩大为完整无障碍认证。

## 节点、关系和选择语法

节点表达系统中的职责或对象。图标区分算法、要求、成品、外部边界等少量类型，名称承担主要辨识工作。纯设计使用虚线轮廓；它不等于实现失败。当前选择使用同一 accent 面与边，焦点使用独立可见轮廓，hover 仅作轻微表面变化，不让图跳动。

关系箭头表达方向。返修反馈用虚线，当前步骤及所选关系适度加强。关系标签和线段调用同一选择动作；节点使用原生按钮处理 Enter 与 Space，避免只改变图组件内部的选中状态而没有打开详情。上下游可在图中聚焦，也可以从详情的关系入口继续探索。

前向关系由 ELK 提供节点位置与正交路线；返回关系使用外围通道，保持对相同 canonical relation 的引用。制作者检查了所有当前图的路线与非端点节点碰撞。正式阶段的复杂图仍需成熟布局约束、分组和局部展开，不能把本轮少量外围通道包装成通用障碍路由引擎。[生成器](prototype/scripts/prepare.mjs)、[图交互](prototype/src/Graph.jsx)

## 四类机制，各有合适的表达

| 内容 | 实际表达 | 需要保护的含义 |
|---|---|---|
| DA 职责与恢复 | 紧凑的步骤、输入交接、边界与返修路径 | 没有代码也可读；未知宿主接线在对应位置保留 |
| Mica 事件与状态 | 事件顺序、守卫、时限、互斥与选择器；继续进入真实函数 | 原生宿主、共享事件、局部恢复不混成泛化功能介绍 |
| CAT 数学与数值机制 | KaTeX 公式、数学含义、算法步骤及对应例程 | 未冻结算法保持开放；反例和参考结果的范围不升级 |
| Tutorial 成品验收 | 页面/对象结构、具体 finding、要求、原文件入口及修复影响 | 页码附属于候选；正确页面不跳到别页的错误；验证器缺陷与课件缺陷分别归属 |

它们使用 [Details.jsx](prototype/src/Details.jsx) 中按内容类型选择的 renderer。标题、页对象和函数身份来自共同模型。页面结构列表明确是对象定位，完整受控原页从固定来源打开，不用仿制截图冒充原材料。

实现栏也遵守对象类型。Artifact 显示“文件”，要求显示“依据”，finding 显示“定位”；这些是同一绑定与来源关系的阅读投影。设计参考文档不会进入生产例程列表。测试定义旁注明它与执行结果的区别，证据栏保留方法、对象和当前结论边界。

代码使用 Shiki 的 `github-light` / `github-dark` token；公式采用 KaTeX 的 HTML 与 MathML。两者在真实主题切换中检查。完整源码和复杂公式允许局部滚动，不能造成整页横向溢出。

## 修订与差异

修订首先解释发生了什么以及为什么。版本标签、触发依据、前后内容和保留范围依次出现；下游检查范围按需展开。无需打开默认巨型时间线，也不为每个提交生成一张卡。

图中变化保留当前位置和必要的历史对象。新增、撤销、修改分别有文字与颜色；scope 外的对象只作当前上下文，不称为历史未变。改接关系保留前后两条显示边，稳定语义 ID 不因显示版本而改变。点击变化图或手机变化列表会出现对应前后内容，不能只换颜色却没有阅读后果。[比较算法与负例](prototype/src/model-core.js)、[模型测试](prototype/scripts/model.test.mjs)

历史材料是本轮重建时，界面说明它不是原始冻结快照。Mica 只比较逐段核过的三对历史函数，其余旧绑定不因缺少重建就被列为新增；CAT 的旧路线有撤销依据，替代算法仍可未定。文案范围与数据范围保持一致。

## 可访问操作与响应式约束

主要移动操作保持至少 44px 的命中高度，图提供等价的对象列表与关系入口。焦点可见，来源弹窗限制 Tab 在内部并在关闭后恢复入口焦点；Escape 关闭当前上下文。手机从列表进入对象时把返回入口置于可读位置，返回时恢复原路径位置。

系统尊重 `prefers-reduced-motion`。当前原型不依赖动画传递不可替代的信息。颜色之外还有文字、线型与对象名称，代码和公式可以选择复制。页面使用明确标题、原生按钮、select、链接和对话框语义，源链接保留原仓库权限。

本轮实际检查 Chromium 中的指针、键盘、主题和多种视口；未声称已经完成真实触屏设备、VoiceOver/NVDA、Safari 或 Firefox 的正式验收。正式交付应依据[交接合同](CODEX_HANDOFF_CONTRACT.md)在目标环境继续验证。

## Whole-product taste gate

制作者先看整屏，再看内容块和文字。一次检查必须能回答：视线是否先到系统，所选对象是否清楚，图和详情是否争抢空间，是否有空标题或重复状态，长路径是否挤坏链接，手机是否真的改了阅读顺序，深色代码和公式是否仍可读。

真实可见内容逐项作 KEEP、DELETE、MERGE、RELOCATE、REWRITE。去掉格式后连续阅读正文，保留每个状态的读者顺序；不把隐藏的另一断点副本当成正文，也不使用禁词计数替代判断。审查表留在研究材料中，不进入产品界面。

制作方已发现并修复的具体缺陷和最终覆盖范围由 [CONTENT_AND_TASTE_AUDIT.md](CONTENT_AND_TASTE_AUDIT.md)记录。P1 与明显 P2 清零只是交给下一轮 Work 的门槛；最终产品取舍继续等待独立比较和用户裁决。
