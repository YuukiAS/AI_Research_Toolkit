# 合成大模型的投影与查询探测

本记录只检查一条有限的数据路线：共同模型保留完整对象，系统图只投影其中 24 个高层节点，局部影响查询继续读取完整前后关系。数据由脚本确定性生成，不代表真实项目，不加入四个 reference 的产品界面。

使用本轮已经安装的 ELK.js 0.12.0 与当前 model-core；环境为 v24.22.1 / linux 6.18.55 / x64。原始结果、代码摘要与运行时间保存在 [large-graph-probe.json](large-graph-probe.json)，复现脚本为 [large-graph-probe.mjs](large-graph-probe.mjs)。

## 实际观察

200 个实体、311 条关系的完整模型，生成 24 个节点、40 条关系的系统投影。ELK 实际执行 layered 与正交路由，图形几何边界为 1341.67 × 972；节点矩形重叠对数为 0。投影耗时 0.1474 ms，首次布局调用耗时 168.4171 ms。只检查了矩形几何，没有检查边交叉、标签、字体或浏览器可读性。

在一个不可见的内部消费者入口删除关系，并修改该消费者的合成机制。以被删关系的产生方为查询起点，完整前后关系并集仍找出 77 个构造时已知的下游对象，全部位于系统投影之外；仅使用当前边或可见边时分别为 0 和 0。完整并集结果与构造的消费者集合一致，说明这个案例不会因删边或隐藏节点而漏掉旧消费路径。局部差异返回 2 项变化。

另运行了 1600 个实体、2407 条关系的同类查询，没有布局或渲染这些对象。它返回 718 个候选影响对象，与构造集合一致。两次完整并集查询分别耗时 6.1934 ms 与 35.4805 ms。

## 能支持到什么程度

这次观察支持所构造案例中“投影范围与全模型查询范围分离”的数据处理方式，以及旧关系参与删除影响追踪。模型只使用向前传递的合成 sends 关系；当前 affectedEntities 仍是候选范围遍历，不等同于正式按关系类型判断因果与证据失效。共同输入在投影与查询后保持不变。

本报告中的每项计时来自本次执行的一次调用，没有预热、重复统计或预设门槛。没有测量 React Flow 交互、帧率、内存上限、手机或屏幕阅读器，也没有证明千节点交互或真实大型项目可用。上述数字不作为最终候选优劣评分或验收结论。
