# 架构设计与冻结合同

## 1. 目标

Asteria 的设计合同用于把“看起来完整的高层图”推进到“实施者不需要发明关键行为的架构”。它不是表格填写竞赛。每一步只在当前项目需要时产生对象，并允许纯设计、科研阻塞和专业判断尚未完成等合法状态。

## 2. 设计顺序

### 2.1 用户能力与边界

先记录用户真正获得什么能力、哪些场景必须成立、哪些不属于本次范围，以及数据、费用、权限、服务商和不可逆操作边界。没有这个入口，后续组件拆分很容易优化错误目标。

### 2.2 核心对象

建立长期稳定、可跨修订引用的对象。对象名称应对应产品、科学或执行语义，而不是当前目录名。文件可以绑定对象，不能反过来把文件树当对象模型。

### 2.3 组件责任

每个 accepted 组件说明它拥有的责任、输入、输出和不变量。只有真正跨边界的行为才需要新组件；算法内部步骤通常属于 mechanism。

### 2.4 关系合同

关键关系说明：生产者、目标、真实载荷、消费者、前置条件、失败含义、恢复含义和保证。装饰线、仅用于分组的 contains 边和低风险注释边不强制完整合同。

### 2.5 关键机制

机制必须解释系统如何工作，而不是再次列组件。根据内容选择状态机、时序、算法、公式、数值例程或成品返修循环。机制说明承担者、输入、输出、不变量、失败模式、重试／取消条件和边界。

### 2.6 正常、失败、恢复与保护路径

路径引用同一拓扑：

- 正常路径证明主要用户能力能闭合；
- 失败路径说明错误如何被发现、传递和消费；
- 恢复路径说明状态如何回到可接受位置；
- 保护路径说明改动之外哪些能力必须维持。

### 2.7 实现责任

为已经实现或即将实现的关键对象定义 repository binding、负责模块、测试和候选身份。纯设计系统允许 implementation 为空；已经声称实现却找不到锚点时才阻塞冻结。

### 2.8 验证方法

区分机械证据、运行证据、真实成品、科学证据和专业判断。验证方法本身不是通过证据。每份证据都绑定候选、范围、生产者、观察、限制和有效期。

### 2.9 开放项

开放项必须有影响范围、退出条件、承担者和是否阻塞。一个模块“尚无唯一算法”可以是合法状态；如果它会迫使 Codex 决定科学方法，就必须阻塞冻结。

### 2.10 Architecture Freeze

冻结一个有意义修订，而不是截图或目录。冻结回执包含 revision、规范图哈希、开放项、结构检查结果、专业判断来源、实现对齐、证据状态、下游影响和不变保证。

## 3. 可机械检查

Asteria 应直接检查：

- accepted 关键组件没有责任；
- 关键关系没有载荷或真实消费者；
- 关系指向不存在对象或路径无法闭合；
- linked implementation 没有固定提交、相对路径或结构锚点；
- 声称 tested／audited／validated 却没有有效证据；
- design-only 对象错误地被标记为 implemented；
- revision 没有 trigger、reason、change、下游影响或不变保证；
- semantic change 没有目标或无法定位 before／after；
- superseded 路线没有触发证据；
- evidence 指向旧候选或相关绑定已 stale／broken；
- design 与 implementation 双向 drift；
- 下游影响集合为空但关键关系发生变化；
- 手机 readingOrder 引用不存在对象；
- 当前投影维护第二套与规范关系冲突的边。

检查结果应给出对象、规则、观察和修复入口，不给出虚假的总分。

## 4. 必须由 ChatGPT／GPT Work／领域审查判断

- 是否漏掉整个用户场景或错误用户能力；
- 产品取舍是否正确、是否过度设计；
- 组件边界和 black box 是否合理；
- 科研模型、定理、算法或统计解释是否成立；
- 成品是否真正可用、可教、可读或视觉成熟；
- 关系载荷虽然有字段，是否真实反映运行行为；
- 证据是否足以支持结论，而不只是存在文件；
- 开放项是否允许在当前风险下进入冻结；
- Codex handoff 是否仍留下关键决定。

这些判断必须形成可定位回执，但不能伪装成 lint。

## 5. 冻结状态

- `DRAFT`：设计仍在形成，允许关键空白。
- `CANDIDATE`：结构检查已运行，等待专业判断或修订。
- `CONDITIONAL_FREEZE`：只有非关键开放项，影响和退出条件已明确；可进入低风险实现。
- `FROZEN`：关键语义闭合，专业判断完成，Codex 无需发明关键行为。
- `SUPERSEDED`：由后续 revision 取代，保留历史。
- `ROLLED_BACK`：当前路线被撤回，保存原因和恢复目标。

结构检查通过不自动进入 `FROZEN`。Freeze 也不等同于发布批准、费用授权或生产部署授权。

## 6. Codex 可接受的开放项

可以留给实施的内容：局部命名、等价库 API 的低风险细节、样式微调、明确边界内的性能参数、已有测试合同下的内部重构。

不得留给实施的内容：用户能力、核心对象、关键关系消费者、数据／权限／费用边界、科学算法选择、失败归属、验证结论、发布门槛和不可逆副作用。
