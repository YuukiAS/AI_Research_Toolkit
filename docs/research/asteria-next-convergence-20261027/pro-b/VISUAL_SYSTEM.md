# Asteria 视觉系统

## 1. 视觉目标

Asteria 的第一眼应是成熟的技术阅读工具，而不是监控 dashboard。视觉优先级是：系统结构 → 当前阅读路径 → 选中对象 → 机制或证据。状态存在但不抢占结构；留白用来建立层级，不用装饰填满。

## 2. 基础语法

### 字体

正文使用系统无衬线字体，代码、commit、路径和结构 id 使用等宽字体。标题只承担页面层级，不使用巨大营销字号。公式由 KaTeX 渲染并保持与正文基线、字号和暗色主题一致。

### 间距与密度

以 4px 基础单位建立 8／12／16／24／32 间距。系统图允许较高信息密度，但 inspector 和正文保持可连续阅读的行距。卡片不是默认容器；只有对象边界、差异、证据或可点击单元需要表面。

### 表面

页面主要使用背景、单一主表面、轻量次表面和必要的浮层。边框主要分隔结构，不为每段文字加框。阴影仅用于浮层、选中对象或独立弹窗。

## 3. 节点与边

节点语法同时表达类型、名称、简短当前状态和选中态。状态颜色只作为辅助：

- accepted／tested：中性或青绿色稳定强调；
- design-only：蓝色虚线边界；
- open：琥珀色；
- blocked：红色；
- superseded：降低对比并从当前路径移出。

边默认安静。当前路径、选中关系和阻塞边逐级增强。边标签只在当前路径或选中时显示；关系载荷和消费者进入 inspector，不在图上铺开。

## 4. 选中与聚焦

同一状态只有一个主要表达位置。选中节点由描边和 inspector 表达，不再在标题、侧栏、toast 和多个 badge 重复。路径外对象降低对比但保持空间上下文；用户可进一步切换层或 trace。

## 5. 差异

before／after 使用对称布局、短标题和事实文本。删除／旧状态使用低饱和红，新增／当前使用低饱和绿；颜色以外还保留标题。结构 token 作为下沉证据，不把原始 diff 覆盖在主页面。

## 6. 机制 renderer

- sequence：水平或垂直步骤，显示状态转移、消息和取消条件；
- algorithm：编号步骤，重点呈现输入、输出、不变量、近似和失败模式；
- formula／numerical：公式、量的定义、routine、oracle 与误差／稳定性证据；
- artifact loop：候选、要求、机械证据、专业判断、finding、返修、重渲染和复验。

renderer 共享 tokens 和交互，不强迫共享相同卡片结构。

## 7. 源码、公式与证据

源码锚点显示 repository-relative path、qualified name、role、commit 和 staleness。commit 默认缩写，完整值可复制。公式使用独立阅读宽度和必要解释，不把 TeX 原文当视觉内容。证据卡只显示标题、观察、候选／范围和状态；内部运行字段进入高级详情。

## 8. light theme

浅色主题使用中性灰白背景、白色阅读表面和低对比网格。文本以近黑和两级灰建立层级；蓝灰作为品牌与当前路径色，青／琥珀／红只表示状态。关系线在高亮前保持安静，但不能淡到水印化。

## 9. dark theme

暗色主题使用深蓝灰背景与略亮表面，不直接反转浅色值。网格更弱，关系线、代码、公式和次要文字单独校准。blocked 和 diff 色降低饱和度以避免发光；选中态依赖描边、宽度和层级，不只提高亮度。

## 10. 响应式

桌面系统页采用路径／图／详情三层。低于 820px 后，拓扑改为顺序路径阅读：步骤、关系载荷和消费者依次出现，详情从底部打开。机制、演进和检查变为单列；项目和主视图进入底部导航。手机不展示桌面图缩略版。

## 11. 可访问性

- 所有节点、关系、页签和路径可通过键盘操作；
- 有跳到主要内容入口和明确焦点；
- hover 不承载唯一信息；
- 状态同时用形状／文字／线型；
- 支持 `prefers-reduced-motion` 与 forced colors；
- 正文、边标签、代码和暗色次要文字满足可读对比；
- 触控目标不小于合理尺寸；
- SVG 具有对象标签，手机提供等价线性结构。

## 12. 整页品味门

交付前按完整页面检查，而不是只看组件：第一眼主次、是否有无意义元素、图文重复、状态重复、留白、内容密度、边和节点碰撞、面板平衡、浅暗主题、手机顺序、去掉 CSS 后连续文本是否仍像成熟技术作者。明显 P2 不留给下一轮审查。
