# R2 候选本地 A/B 结论

## 1. 总体赢家

**A · GPT-6 胜出。** 两份候选都通过了“首页完整架构”和“成熟中文产品表达”两项门槛；差距不大，但 A 在真实阅读和操作中更稳定。

## 2. 最终分数

- A · GPT-6：**86 / 100**
- B · GPT-5.6：**82 / 100**

## 3. 决定胜负的实际差异

1. A 的完整架构在 1600 × 1000 首屏内更容易扫读；B 的中心区域连线、标签和状态信息更密，局部关系需要更久才能理清。
2. A 的情境交互能沿 19 个步骤逐步解释正常、失败返修和旧功能保护；B 的情境信息确实变化，但主要停留在单层路径摘要。
3. A 的关键连接可以直接用鼠标和键盘打开；B 的连接可用键盘进入，但真实指针点击会被上层标签或元素截获。
4. A 的手机页保留完整拓扑且没有横向滚动；B 的手机页重排更利落，但弱化了连接关系，并留下一个 820 px 宽、只能在 362 px 容器内横向拖动的比较表。
5. B 对“已有 / 拟议 / 待验证”的可见状态编码更强；A 的证据追溯更完整，但页面上的状态分层没有 B 那么醒目。

## 4. 值得从 B 吸收的优点

- 节点详情中明确列出“负责什么、不负责什么、当前缺口”。
- 用状态点、线型和文字同时区分已有、拟议、待验证与按需关系。
- 组件数据、交互脚本和样式分离，静态资源更轻，后续局部维护直观。

## 5. 正式实现基线

建议以 **A · GPT-6** 为正式实现基线。它更能保持“先看懂整体，再沿节点、连接和失败路径深入”的设计意图，也更不容易在正式实现中退化成说明卡片集合。

## 6. 当前仍无法判断的事项

- 两份页面都只是设计原型，不能证明 Delivery Assurance、Bridge Kit、宿主 Codex 与原任务之间的生产接线已经存在。
- 失败证据能否稳定回到原任务、候选身份能否贯穿重跑、末端入口能否真正阻止绕过验收，仍需在一个真实仓库中做纵向试点。
- 当前测试没有覆盖屏幕阅读器的完整朗读顺序、低性能设备和真实生产数据规模。
