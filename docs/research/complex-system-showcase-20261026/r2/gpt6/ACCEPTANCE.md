# 后续 Codex 开发验收约束

本轮授权终点是设计与静态交互原型。以下约束用于后续经用户另行授权的正式制作；不能据此启动 Delivery Assurance 产品开发或发布网站。

## 不得降低的结果

- 桌面首页主要区域直接出现完整架构，14 个当前对象、16 条关系与按需分组可辨认。迁移项目可以改变数量，但不能用职责卡片、阶段标签或附件图代替全图。
- 图中实线/虚线、方向、当前性与来源一致。DA 不接管项目专业判断，Bridge 不接管交付判断，按需技能不得成为强制串行流程。
- 点击每个组件显示存在理由、职责、输入、输出及消费者、删除损失和现状；真实上下游高亮。点击每条边显示准确内容及实际接收者。
- 正常交付、错误回原任务、旧功能回归在同一拓扑上依次解释；改变情境确实改变高亮与文字，不能只换颜色或标题。
- 手机重新排图，保留完整关系；触控、键盘、关闭和焦点返回实际有效。不得简单把桌面图缩到一屏。
- 历史 Lucerna 事实、故意错误候选和假设旧功能回归明确分开。旧研究通过不能替代宿主接通、同任务消费和生产启用证据。
- 来源与估算的限制就近保留。4–8h / 40–88h / 138–332h 是相互包含的旧估计，不是已花工时或新预算。

## 内容与视觉准入

新增一个标题、图形、控件、段落前，必须说明读者靠它多理解或完成哪一件事。如果现有元素已经说明，优先删除或合并。Artifact Curation、Reasoned Design、Clear Writing 在这里是取舍、论证和表达要求；名称不能作为质量证明。

保留现有浅灰/白/深蓝的层级、直接的对象名称、非卡片正文与主图优先的面积分配。改字体、字号、间距、色彩或布局后要实际重拍。不得擅自添加大字口号、品牌故事、全局渐变、装饰图标、迷你地图、自动动画、聊天窗口、登录、点赞或无目标的 dashboard。新需求确有必要时另作设计决定，不靠组件库默认样式自动扩张。

逐句审校覆盖最终实际 DOM：静态正文、SVG 标签、按钮、动态步骤、节点/边详情、折叠与手机。记录原文、位置、保留/删除/合并/重写、最终文案与理由；专业事实绑定来源。修改后连续阅读纯文本，再完整复看页面。不能用禁词扫描、中文占比、插件加载、自动评分或“全部合格”代替作者编辑。

## 最小真实检查

`node prototype/build.cjs` 生成单文件 HTML。浏览器验证脚本为 `checks/verify.cjs`，使用外部 Playwright/Chromium；通过 `PLAYWRIGHT_MODULE` 与 `CHROMIUM_PATH` 指定已有安装。它检查实际点击、14 个节点、16 条边、三情境 19 步、首尾控制、双端文本、320–1440 CSS 像素宽度、键盘、无脚本及截图前后的源码身份。它不评价中文自然度，也不证明 DA 可工作。

作者必须打开真实截图检查连线、文字边界、首屏全貌和手机长图，不能只看脚本退出码。视觉返修后重建并重跑受影响验证；最终全部截图从同一源码生成，记录 SHA-256。源文件中任何一句后改文字，都需要重新生成截图与文字清单。

手机模拟不等于真机，键盘操作不等于完整屏幕阅读器验收。本轮未测项保留在 QA 中。正式网站若需要支持 Safari、真实 iOS/Android 或特定读屏器，应在相应设备补验，不得把本轮 Chromium 结果扩大。

## 一票否决

缺完整架构、中文仍明显模板化、关系载荷没有真实消费者、交互只是装饰、截图与源码不同版、把计划写成事实，任意一项出现均返回制作端修正。不要让用户承担第一轮找错。代码和视觉正确也不能抵消内容错误。

交付后停止，不运行产品验收、宿主接线、自动返修、七仓 rollout 或部署。后续发布由用户另外决定。
