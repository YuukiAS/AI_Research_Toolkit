审查对象是最终浏览器中的 272 个独立文本 ID，含首页、图内标签、节点和连接详情、三情境全部步骤、折叠依据、手机与无脚本提示。完整逐条原文、最终文案、取舍理由、出现状态与来源在 [COPY_EDITORIAL_AUDIT.tsv](COPY_EDITORIAL_AUDIT.tsv)；实际浏览器提取在 [checks/visible-text.txt](checks/visible-text.txt)。ID 用于制作端追踪，不出现在网页正文。

作者完整阅读 CUHK Date 150 条审查、Frontend #89 与最新写作 TODO 后，先删除无用内容，再编辑保留的文字。已安装的 Frontend Design / Clear Writing 规则实际用于内容取舍、自然表达与事实保真；没有把插件名称、加载成功或机械检查当作语言验收结论。

## 整页取舍

R1 的英雄区宣言、英文栏目小标题、阶段摘要与职责卡片共同挤走了系统本身。R2 首屏只留下系统名称、中文作用、一个现状说明和完整图。组件的五项详细解释只在选择后出现；证据细节在正文折叠中，不把研究协议编号排到首屏。

手机初稿把无效的前后步按钮和默认读图说明留在图前，图被推到很后面。最终在“全部关系”状态去掉无效步骤控件，手机也省去重复的读图段落；切换情境后，步骤说明才出现。按钮的存在由当前阅读需要决定。

案例正文和证据折叠原先都复述“该轮未构建 Windows 正式版本”，连续读起来像重复免责声明。最终案例只讲误报与修复目标，未做原生验收的限制集中保留在带原始来源的证据段。

## 本轮实际返修

- 页眉与主标题曾重复 Delivery Assurance。主标题改用中文解释对象，页眉保留系统名称。
- “绿色结果”“义务提取”“保留缺口”“测试和实际软件各对一半”分别改成具体检查、验收范围、能否交付和版本错配。
- 最后连读又改写了“同任务消费”“多插件消费确认”“结果消费”和“保持未证”。详情直接说明原任务是否收到并处理、技能结果是否被后续步骤使用，以及验收是否完成；这次修改也重新生成了全部截图。
- “最小一条交付链”改为“下一步怎样验证”，不要求读者先理解内部简称。
- 手机要求节点曾把“旧行为”拆成单字一行，改成“已接受的旧功能”，保留原义并删除可由标题推知的部分。
- 默认说明曾只解释上、中、下三层，手机重排后不成立；改为说明参与者和证据的关系。
- 组件、边和场景中的专业事实保留准确限定：历史问题用过去时；故意错误和旧入口回归明确是构造的情境；未接通的路径不用已完成口吻。

## 连续阅读与范围

已脱离 CSS 连续阅读全部实际提取文本，再完整查看桌面与手机渲染。检查了相邻信息是否重复、标题能否引导、产品专名是否必要、长句是否同时塞入太多责任，以及图内标注能否独立理解。重复的三情境起始步骤保留，因为读者每次只查看一种情境；不在一个屏幕并列展示三套相同文字。

审校是本轮作者完成的编辑工作，没有独立中文评审者、AI 检测器或自然度分数。浏览器脚本只核对文本是否真的出现、内容是否与审校源一致；不能据此推断语言自然。后续若改变一句文案，需更新逐句记录、重新阅读受影响页面，并重新生成截图。
