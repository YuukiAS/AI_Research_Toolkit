# 原型渲染与交互检查

## 检查对象

- `prototype/index.html`
- `prototype/styles.css`
- `prototype/prototype.js`

原型无外部运行依赖；正式工程选型仍是 Astro。本轮没有启动 Delivery Assurance 产品开发或网站部署。

## 实际渲染

使用系统 Chromium 将 HTML、CSS 和 JavaScript 实际载入。浏览器预览环境限制了本机 URL 导航，因此自动检查使用同一文件内容内联到空白文档；布局、交互和样式与提交文件一致。

- 桌面检查：1440 × 1100 视窗，并生成 1440 × 4811 全页图检查整体节奏。
- 移动检查：390 × 844 视窗，并生成 390 × 7191 全页图检查单列重排。
- 组件与证据区分别定位检查，没有整页横向溢出。
- 可审阅交付使用 `prototype/index.html` 与 `prototype/mobile-preview.html`；不以压缩截图替代真实文字和交互。

## 自动交互检查

- 切换到“发现失败”后，结论更新为失败回传。
- 选择第五阶段后，详情明确包含返回原任务与重新修复。
- 选择 Bridge Kit 后，标题与状态同步更新，且不显示为拟建插件。
- 390 像素视窗中 `document.body.scrollWidth === window.innerWidth === 390`，没有整页横向溢出。
- 桌面与移动浏览器控制台均无脚本错误。

## 人工视觉检查

- 首屏在不读流程图的情况下能看到用途、已完成与未完成。
- 任务链主卡只展示一个当前阶段，避免五张说明卡同时争夺注意力。
- 组件列表与合同区域的状态一致，删除后果使用单一高风险强调区。
- 证据账本把“支持”和“不支持”并列，设计、源码和缺证使用文字与颜色双重区分。
- 移动端五阶段变为纵向；组件列表只做局部横向滚动；正文不依赖缩小桌面图。
- 没有装饰插图、自动播放、拖拽画布、发光、拟物控件或无意义动效。

## 已知边界

- 原型只有一页，最终模板会按系统概览、场景、组件、证据与决定分路由。
- 原型内容写在 HTML/JavaScript 中；正式实现需迁入 Astro 内容集合并加模式校验。
- 本轮未做真实屏幕阅读器矩阵、正式 WCAG 审计、性能预算测量或跨浏览器设备实验；这些是产品实施验收，不应由静态设计原型冒充完成。
