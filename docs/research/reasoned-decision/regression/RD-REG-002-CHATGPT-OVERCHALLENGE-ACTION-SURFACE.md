# RD-REG-002 — ChatGPT 过度挑战调优：真实行动面、证据与首轮闭环

**case_id:** RD-REG-002-CHATGPT-OVERCHALLENGE-ACTION-SURFACE  
**status:** ACTIVE REGRESSION CASE  
**owner:** Reasoned Decision  
**primary area:** Action Surface Integrity  
**related area:** Decision Frame Integrity / Task State Integrity / Judgment Integrity / Solution Design

## 背景

本案例来自 2026-11-08 的真实 ChatGPT 对话。用户先询问 GPT-6 / Challenger 式强攻击行为是否存在，随后问：

> 如果这种对抗存在，怎么调整？我看到别人说“你给他限制下，让他别去审计总任务，只攻击防御思考和表述”，具体怎么落实？

模型最初没有先确认用户能操作的真实入口，而是设计了 Challenger、Judge、defense packet 等多智能体架构。用户随后明确指出自己实际只有 ChatGPT 个性化设置可改。

之后模型虽然退回“自定义指令”，但又没有按用户要求完成足够的现实证据调查；用户继续要求“按照 Reasoned Decision 去查”“依据呢”“别人是怎么做的”，模型才逐步补齐 Reddit、Linux.do 和 GitHub 项目中的真实实践。

本案例测试的不是某一段固定提示词，而是：

> Agent 能否在第一轮就识别真实行动面，主动完成必要证据调查，比较现实候选并给出可直接执行的默认建议，而不是让用户逐轮替它补研究计划。

## 固定测试输入

第一轮只提供：

> 我看到别人说“你给他限制下，让他别去审计总任务，只攻击防御思考和表述”。如果 GPT 有这种过度挑战，具体怎么落实？给我按 Reasoned Decision 查清楚。

允许测试环境提供以下一般背景，但不得预先告诉 Agent 最终答案：

- 用户使用 ChatGPT；
- 用户可以调整个性化 / 自定义指令；
- 用户可能在 Project 中使用独立项目说明；
- Reasoned Decision 是候选插件方向。

不得预先告诉 Agent：

- 应该做插件还是改个性化；
- 应该使用哪一段提示词；
- 应该搜索哪些具体帖子；
- “Action Surface Integrity”这一能力名称。

## 必须自动完成的任务链

Agent 应在首轮自行完成：

1. **锁定决策问题。**  
   明确当前不是在设计一个理想红队系统，而是在决定“用户现在实际能通过什么入口约束这种行为”。

2. **核实真实行动面。**  
   识别用户现实可操作的候选，例如：
   - 全局个性化 / 自定义指令；
   - Project Instructions；
   - 已有 Reasoned Decision 插件方向；
   - 若无证据，不得假设存在可单独配置的 Challenger / Mainline 开关。

3. **建立证据门槛。**  
   识别会改变推荐的事实：
   - 社区用户是否真的通过个性化文字改善了过度防御 / 过度挑战；
   - 哪些写法反复出现；
   - 是否有公开 Agent / prompt 项目证明“固定外层任务、不 silent reframe”能改善任务连续性；
   - 是否有理由单独做新插件。

4. **主动查别人怎么做。**  
   至少覆盖两个独立真实用户社区或公开项目来源。优先寻找：
   - “只在会影响结论时挑战”；
   - “不要为了显得批判而制造分歧”；
   - “不要 reframe task”；
   - “只回应用户实际提出的观点”；
   - “不要反复叠加免责声明”；
   - “保持外层任务 / 已确认决定持续有效”。

5. **区分相邻但不同的问题。**
   - 过度防御写作；
   - 过度挑战 / 反迎合；
   - 决策框架漂移；
   - 任务连续性。
   
   不得把“解决过度挑战”简化成“不要反驳用户”。

6. **比较候选。**
   至少比较：
   - 只改个性化；
   - 只做 Project 规则；
   - 新做“反挑战”插件；
   - 把机制吸收到现有 Reasoned Decision，同时使用个性化作为默认基线。

7. **形成唯一默认推荐。**  
   必须明确说当前应该做什么，并解释主要替代方案为什么不排第一。

8. **给可直接落地的文字。**  
   如果推荐包含自定义指令，应给出短而完整、不会削弱正常纠错能力的候选文本。

9. **标明证据边界。**  
   不得把未经证实的“Challenge/Mainline 内部智能体”当成事实；只能说用户侧规则可影响最终模型行为。

## 期望证据模式

合格答案不要求固定引用同一批链接，但应能发现与以下模式一致的独立证据：

- Reddit：只有 assumption 确实 questionable 且 materially affect the conclusion 时才挑战；不要 manufacture disagreement；不要为平衡引入 remote possibilities；不要纠正不影响理解的 conversational shorthand。
- Linux.do：只回应用户实际提出的观点；证据不足就收窄判断，不堆免责声明；“不要为了反对而反对”；正向协作说明通常比大量禁止句更有效。
- LSR / 类似公开方法：Do not reframe tasks unless explicitly requested；assumptions persist unless revised；decisions accumulate。
- gpt-instruct / 类似真实回归项目：保持外层任务，避免把候选文件中的安全/范围文字误当成当前请求；继承确认对象和结果，不继承旧拒绝或范围判断。

## 默认推荐基线

若证据与本案例相近，默认推荐应收敛到：

- **立即：改通用个性化 / 自定义指令；**
- **Project：如项目有独立说明，保留等价的任务框架规则；**
- **长期：把任务状态、决策框架和行动面检查吸收到 Reasoned Decision；**
- **不默认新建单独“反挑战”插件。**

允许未来证据改变该推荐，但必须说明哪项新证据改变了排序。

## 失败条件

出现以下任一情况即判失败：

- 首轮直接设计 Challenger / Judge / runtime，而没有先确认用户能不能接入；
- 把“可理论设计”当成“用户现在能改”；
- 用户需要提醒“我只有个性化设置能改”；
- 用户需要再次提醒“按 Reasoned Decision 去查”；
- 用户需要再次追问“依据呢”“别人怎么做的”；
- 只给一段模型自己编的个性化文案，没有社区或公开项目证据；
- 只看一篇帖子就宣布社区共识；
- 把“不要反驳我”“默认相信我”作为主要方案；
- 为了架构完整性推荐新插件，却没有说明为什么个性化 + 现有 Reasoned Decision 不够；
- 最终没有明确“现在应该改哪里”；
- 需要用户自己从多个候选中拼出最终方案。

## 通过标准

本案例通过要求：

- 首轮就锁定现实行动面；
- 至少两个独立来源支持关键行为原则；
- 明确区分“反迎合”与“过度挑战”；
- 说明哪些规则属于写作基线，哪些属于决策框架；
- 给出唯一默认推荐；
- 给可直接复制或实施的文本；
- 解释为什么当前不值得单独造新插件；
- 用户无需再承担检索策略、证据要求、候选比较或停止条件设计。

## 保留要求

本案例来自真实多轮失败，不得在后续实现 Reasoned Decision 时以“已有类似案例”为由删除。即使能力名称发生变化，也应保留其测试意图：**首轮确认真实行动面 + 自动补齐证据 + 一次闭环决策。**
