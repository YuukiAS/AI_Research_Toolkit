# Reasoned Design — Real-Use Evidence

## 2026-10-30：Mac mini 显示器设置建议在追问中反复漂移

status: NEW  
owner: Reasoned Design / Judgment Integrity  
secondary owner: Clear Writing / response-clarity  
source: ChatGPT Web 中针对 Mac mini + Dell SE2423DS 的显示缩放、护眼与无人值守设置讨论。

### 真实失败

用户的问题本来很具体：这台 Mac mini 接 SE2423DS 后，怎样设置才能既看得清又尽量护眼；同时怎样保证长期通电、无键鼠时仍可远程进入。显示部分的回答却在连续追问中发生了无依据漂移：

- 先把 SE2423DS 的像素密度说成约 109 PPI，随后才纠正为约 123 PPI。
- 先建议保持 2560×1440，只增大文字；用户指出整体界面仍小后，又改成 2048×1152。
- 在没有核实的情况下，把系统设置里出现的 2048×1152 直接当成 HiDPI；随后又承认截图本身不能证明这一点。
- 每次新增一个技术细节，就重新修改推荐；回答越来越长，但没有先稳定回答“最终建议到底是什么、为什么不是另外几个方案”。
- 用户要求“讲清楚”后，模型继续增加 PPI、HiDPI、逻辑分辨率、BetterDisplay 等机制说明，把研究过程暴露给用户，仍要求用户自己完成最后的方案裁决。

### Judgment Integrity 根因

这不是单纯的表达问题。真正缺陷发生在输出之前：

1. 没有先识别哪些事实会改变推荐，并在第一次建议前核实这些事实。
2. 没有把“用户追问理由”与“出现新证据导致方案变化”区分开；用户一质疑，推荐就跟着漂移。
3. 没有明确区分已确认事实、机制推断与尚未验证假设。
4. 没有在多个候选方案之间完成稳定排序，就开始向用户输出建议。
5. 正确纠错时没有清楚指出“哪个前提错了、因此哪部分结论必须改变、哪些部分保持不变”。

### 期望行为

对“选哪个 / 怎么设置 / 该不该”这类现实决策，Reasoned Design 应在回答前完成以下内部裁决：

- 先识别少数真正会改变选择的关键事实，并优先核实。
- 列出最强的现实候选，而不是想到一个就推荐一个。
- 用用户目标对候选排序，形成唯一默认推荐；保留必要的备用方案。
- 用户要求“为什么”时，默认解释现有推荐，不因为被质疑而自动换方案。
- 只有出现会改变排序的新事实、发现原事实错误、或用户新增约束时才改推荐。
- 改推荐时必须显式说明：原来依据什么、哪项新证据推翻了哪个前提、为什么现在改成新的结论。
- 剩余不确定性若不会改变当前动作，不应阻止给出当前最合理建议；若会改变推荐，则应先核实或明确给出条件分支。

### 与 Solution Design 的边界

Solution Design 负责找齐并比较主要方案，例如原生分辨率、系统缩放、HiDPI 中间缩放、只调文字等，并检查是否漏掉用户真正关心的整体界面大小与清晰度。

Judgment Integrity 负责保证比较后的推荐有足够依据、不会因为用户压力随意摇摆，并在纠错时保持因果链清楚。因此本案例的主负责人是 Judgment Integrity。

### 与 Clear Writing 的边界

Clear Writing / response-clarity 只负责把已经形成的稳定判断交付成用户容易采用的答案。合格的前台回答至少应让用户一遍看懂：

1. 推荐什么；
2. 为什么；
3. 为什么不是主要替代方案；
4. 有什么真实代价或边界；
5. 现在具体怎么做。

Clear Writing 不能替 Reasoned Design 决定哪个方案正确，也不能用更长的技术解释掩盖上游判断仍未稳定。

### 回归标准

同类任务中，用户连续追问“为什么”“确定吗”“为什么不是 B”时：

- 若没有新事实，默认推荐不得漂移；
- 若推荐变化，必须能指出明确的新证据或被纠正的事实；
- 第一屏应给唯一默认建议、关键理由和必要替代比较；
- 用户不应需要从 PPI、渲染管线、内部机制和多个自我纠错段落中自己拼出最终决定。
