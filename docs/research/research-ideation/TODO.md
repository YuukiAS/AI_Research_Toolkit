## 1. 方法可以是起点，但问题要尽早落地

导师和组会听到的多是别人的方法，从方法出发很正常。问题在于拿着方法太久，问题迟迟不落地。候选规则：第一次花 GPU 之前，问题必须写清楚：谁会因此吃亏、在哪份数据上、最强的简单做法输了多少。

待定：多早算“尽早”；写不清时是停下，还是先做小实验去探。

## 2. 前作一票否决：怎么判、谁来判

DII 实验 5 的教训：实验前的知识边界审查已经说大部分问题被解决，只剩一条弱的开放项，仍然开跑；结果正好落在 DR 预先描述的经典微调折中里。

候选做法：
1. 实验前写“主张”：结果最好时要说的那一句话。
2. 主张逐条对前作，每篇只给三种判定：
   - 已覆盖：同一现象，设定相同或更宽，证据可靠（有正文数据，不是只有摘要）；
   - 部分覆盖：设定不同，必须说清这个不同为什么会改变结论，说不清就按已覆盖算；
   - 未覆盖。
3. 分工：DR 找候选前作（只查事实）→ Codex 回原文核对关键句和数字 → 新开对话的 GPT Pro 逐篇判定是否覆盖，并给出依据（不评价方向）→ 用户与 Claude 做最终决定。
4. 否决规则：主张被任一篇可靠前作判为已覆盖，默认不跑；用户和 Claude 可以推翻，但必须写下理由并记录。

### 2a. 补充：把主张拆成四项再逐项对前作（2026-11-22，未启用）

来源：小红书 007 号帖（CCHAO4，“Codex 给的创新点，为什么我不敢直接用”），辅以 018、008、011 号帖。材料在本仓库分支 `research/xhs-ai-research-ideation-20261122`。上面第 2 步“主张逐条对前作”太粗，判定容易凭整体印象。改为：

1. **拆主张。**把主张拆成四项：研究对象（什么任务、什么数据）、方法变化（具体改了什么）、条件（例如多少中心、怎样的异质性、多少标注）、结果定义（用什么量衡量、在哪里测）。拆不清的项先追问，拆清之前不检索。
2. **从宽到窄检索。**先查“对象 + 条件”（这个问题有没有人研究过），再查“对象 + 方法 + 条件 + 结果”（找最接近的前作）。每次记下数据库、检索式、日期。
3. **逐项比对。**每篇相近前作，四项各判“相同 / 相近 / 不同 / 未知”，每项注明原文出处。材料不够就写“未知”，不许补全。“论文没提到”不等于“论文明确没做”，“搜不到”不等于“没人做过”。
4. **判定规则（替代上面的三种判定）：**
   - 四项都是相同或相近 → 已覆盖；
   - 只有“方法变化”一项不同（换模型、换数据、调参数）→ 默认已覆盖，除非能说明这个改动让结论变了；
   - “条件”或“结果定义”有一项不同 → 部分覆盖，必须回答一句：这个不同改变了哪条已有认识（018 号帖）。答不出按已覆盖处理；
   - 有“未知” → 不判，先回原文补证据。
5. **另外问一句“没人做”还是“没人关心”**（018 号帖）：没人做但也没人提过需要的，要额外说明谁会因此受益。
6. **隔离判定**（011 号帖）：每篇前作的逐项比对交给一个新开的对话，只给它主张的四项和这一篇前作的原文，不给其他候选和之前的讨论，以减少锚定。
7. **记录：**每个主张一份查新记录，六项：候选主张、检索记录、最接近的前作、真实差别、证据与未知、下一步（继续 / 修改 / 放弃，由用户和 Claude 定）。

待定（2a 新增）：
- 我们的场景里，“条件”这一项通常就是中心数、中心间差异、标注量。它的“不同”是否太容易成立，需要用一个真实候选试一次才知道；
- 第 6 步每篇前作开一个对话，成本是否可接受，还是只对最接近的 3 篇做。

待定：
- “可靠”的门槛（摘要、预印本、单中心算不算）；
- 部分覆盖时，谁来判断“这个不同是否改变结论”；
- 推翻否决的理由需要满足什么条件；
- 是否所有实验都要走这一步，还是只针对要投入较多算力的实验。

## 3. GPT 不得擅自改写发给 DR 的提示词

DII 第 1 轮 DR17 三份结果很差。仓库里的提示词要求机械地建清单、逐字摘出各论文的局限；实际发出的是 GPT 改写后的版本，把任务改成了“找剩余困难”这类要下判断的综合任务，同时丢掉了篇数要求和原文摘录要求，改写版本也没有进仓库。DR 本身也偷懒（5 篇论文、参考文献注明“格式为示例”）。

候选规则：发给 DR 的提示词以仓库版本为准；GPT 要改，必须先推进仓库，让用户和 Claude 看到改了什么。

待定：是否写进 DR 任务设计规范，以及 GPT 端的执行办法。
