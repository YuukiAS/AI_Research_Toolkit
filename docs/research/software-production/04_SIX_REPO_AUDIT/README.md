# 六仓库问题与具体防护：从这里开始读

更新：2026-10-13。沿原研究分支继续，没有重建方案、没有启动Critic、没有修改产品或发布。本目录是证据整理与机制论证，不是一套已经验收的软件生产框架。

## 本轮得到的实质结论

**现有问题不是统一缺少一个工作流插件或一个验收器。** Mica的活动重构分支已经有验收CLI、`validateBundle`与同路径正反控制，仍出现观察/归属/证据绑定的多轮返修；Asteria有大量真实浏览器测试，但部分指标函数没有观测自己声称的性质；CUHK Date曾有“托管预检”，却使用另一种密码并绕过真实表单而假绿。单纯集中、冻结和强制运行这些组件，不会自动解决问题。

另一方面，现有组件里已有值得保留的能力：SeminarArc真实安装包黑盒能抓到服务生命周期崩溃，也能暴露测试器自己的误判；Bobbio已有明确的Zotero数据隔离和分层产品审查；Lucerna已有同次进程、窗口和截图绑定。把这些全部重写成一个中央系统同样没有依据。

本轮将已有六份账本中的**246项问题、源码检查缺口和产品边界**逐项映射到具体脚本/函数/专业角色，给出其实际观察、能拒绝什么、还不能证明什么和应补哪个环节。它们不是246个当前故障，也不表示历史已经穷尽。

## 这次真正执行了什么
