## 结论

建议建立独立版本化的“研工台”运行包，包含**任务监督进程、实际Codex调用、项目检查适配、独立测量与产品审查、受控交付**。它不是再增加一个Skill或可信验收脚本，也不是Bridge大版本。插件提供专业能力，Bridge提供合法执行/工作树/既有恢复机制，六仓库仍拥有业务、设计与平台测试。

必须补上的不是更多“禁止偷懒”文字，而是：先核实完整产品目标与真实依赖；在实现早期走通真实纵向路径；校准检查器是否能看见自己声称测量的性质；在用户/GPT Work之前完成内部真实运行与独立完整画面检查；根据根因返修同一个任务；真正安装/发布前核对精确产物、权限和目标状态。

## 为什么旧路线不足

这次补读Lucerna 01056至01056r3原始评审，明确了先前摘要没有充分覆盖的事故：安全存储事务失败、前端清理被原生隐藏旁路、真实提供方schema不符、依赖未实现却关闭下游待办、生产状态与fixture词汇不一致、49/92个证据摘要不符，以及只有设置/折叠状态却声称完整产品。

同时补读Asteria RC7/RC8/RC13：之前GPT Work整组通过之后仍被用户整屏观察推翻；RC13还揭示SVG与HTML不是同一屏幕坐标系、百分比中心与固定像素尺寸混用。原有函数把指标设0的局部反证继续保留，不重复包装为本轮跑过完整应用。

这些证据推翻两种简单答案：把原脚本锁住强制执行，会锁住错误观察；再叫一个模型审查，会重复漏掉相同类型的整屏问题。必须同时校准测量、检查真实动作、把设计检查提前，并处理权限与恢复。

## 本轮核对到的正面现状也必须保留

`cloudflare_r2.rs`当前已经有明确响应类型、真实refresh、部分数据处理、保存事务与失败注入测试。因此示例不重做R2，而是在已有实现上说明新增提醒功能怎样真实交付。Mica活动分支已经有验证器/正反控制；SeminarArc已有真正安装包黑盒；Bobbio已有隔离Zotero和分层审查；Asteria已有实际浏览器检查；CUHK Date已有真实注册关键路径。不能为新架构的存在理由把它们全部说成无效。

## “所有问题”和“一次性”的边界

本版将已登记246项全部经既有CSV映射到K01–K12的具体控制接口，又补充20项Lucerna、5项Asteria细化观察；这些含重叠根因，不能相加伪称更多独立事故。历史已修复、源码缺口、风险边界与实际未完成分别保留。

尚未逐条遍历六仓库全部历史提交、评论、旧分支和私有原始图像，故不宣称历史穷尽。原[覆盖表](../04_SIX_REPO_AUDIT/COVERAGE.md)仍适用；其中本轮已补读的Asteria RC7/RC8/RC13、Lucerna01056四份独立FAIL在补查页列出，其他缺口不被隐去。

一次交办是让常规实现、检查、发现问题和返修在内部同一任务完成，不是承诺第一份代码无bug。已知事故必须有能拒绝复发的测试/观察与权限机制；正确产品也必须能通过。未知未来缺陷不能由有限测试或视觉模型保证永不发生，这不能成为允许已知假数据、恒零度量或缺证据通过的借口。
