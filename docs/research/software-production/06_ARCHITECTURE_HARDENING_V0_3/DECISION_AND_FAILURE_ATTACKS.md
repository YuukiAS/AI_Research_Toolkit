# 研工台 v0.3：v0.2 架构漏洞、反证与修订决定

日期：2026-10-13。性质：Planner 自行反证并修订，不冒充独立 Critic；未实施程序、未获系统上线和六产品修改授权。此研究继续放在用户允许的原分支，未来代码归属尚未决定。

## 一、核心修订：不再默认建立第二套软件开发状态机

v0.2 选择独立 TypeScript 监督程序驱动所有任务，但真实 Bridge Kit Reviewed 已有任务状态、Controller、Codex watcher、Planner→Executor→Reviewer，Control 另有 Verifier；同一个任务再引入一个有推进权的监督进程，会产生双重派单、重复执行、错误恢复和预算互相覆盖。

**v0.3 推荐的对象仍称“研工台”，但产品形态改为可版本化的“软件产品交付能力包”，而不是无条件常驻的第二个执行内核。** 它提供完整产品路径准入、变更与回归选择、观察器校准、质量证据与候选真实性、有限交付控制。开发执行与寿命仍由已安装的 Codex、Bridge 或项目既有合法运行入口拥有。必要时有一个轻量本地驱动器，但只能为没有 Reviewed/Control 状态拥有者的普通 Lite 任务服务。

命令行、GitHub 事件和用户看板是接入方式，不是架构全部。对已有 Reviewed/Control 任务，只能被动消费其已批准阶段并返回质量结果，不得复制或直接改写 CURRENT、启动第二个 watcher、创建另一个审查者链或擅自变更审批预算。若当前没有实际有权调用远端执行的聊天工具，“在 ChatGPT 中说继续”只是请求，不能谎称已自动开始运行。

## 二、二十个会直接导致旧提案失败的设计漏洞

| 编号 | 当前漏洞与因果风险 | 真正要新增或复用的决定性机制 | 必须发生的反证 |
|---|---|---|---|
| H01 | 监督程序与 Bridge Controller 同时拥有任务推进权，可能双启动或改错任务阶段 | 由 Bridge 当前模式判唯一状态拥有者：Reviewed/Control 使用原 CURRENT 和 watcher；研工台仅提供按阶段允许的检查/结果。Lite 无状态机才允许本地薄驱动器 | 重复发送同任务事件，Codex 只启动一次，CURRENT 只发生一次合法转移 |
| H02 | 聊天入口没有可调用执行器，流程停在提示词 | v1 区分本机命令/Codex/Bridge 实际入口与尚未安装的聊天连接，执行前核对工作目录、登录身份和执行主机；没有执行者即真实暂停 | 发起普通任务取得真实执行进程、改动和检查；未接通的路径不能出现 RUNNING |
| H03 | “内部独立审查者”只是角色名称，实际无人执行 | 分开生产者自检、实际可调用的独立审查与仓库要求的 GPT Work；审查者必须取得完整真实画面或运行对象及候选身份；不存在合法启动入口就待审，不借 Codex 自评冒充 | 旧图、精选裁剪、不可访问材料不能产生独立完整产品通过 |
| H04 | 直到最终候选才看整屏，错误产品方向会导致十轮返修 | Frontend Design 的产品交互、视觉方向、设计系统，在首个可操作纵向原型时介入；关键状态与整体层级先确认，再大范围编码。普通微修沿已有设计 | Asteria 历史整屏错误在铺开更多页面前被发现，良好原型不被过度阻塞 |
| H05 | 假输入或直接 API 绕过 UI 被当成真实功能 | 项目现有真实用户驱动为最终入口；仅替换外部 I/O，后续正式解析/业务/聚合/交互不得有测试专用最终状态。每条能力声明指定最低证据类别 | Lucerna FIXTURE 旁路、CUHK Date 用 API 代注册、Mica 夹具代宿主必须无法得到真实能力 PASS |
| H06 | 错误测量器即使冻结也会稳定给错误结果 | 对拟判定的性质校准真实正例、已知坏例和缺测例；测量对象和实际观察绑定。Asteria 恒零与 SeminarArc OCR 误读分别证明假阳性和假阴性 | 真坏实现应失败，真正好实现应通过，观察器失灵归工具而非产品 |
| H07 | 旧功能和旧测试一起删除，候选报告仍能绿色 | 已接受用户行为和关键正式检查来自不受候选写权限控制的批准来源；合法测试迁移需证明每项旧行为得到新测试接管，不能只看旧实现字符串 | 删功能连同删测试仍拒绝；合法内部实现重构不因过时代码断言而永远失败 |
| H08 | GitHub 被跳过的必需检查显示成功，同名伪造也能误放行 | 发行准入使用预先确定的必需检查集合，核对检查来源、实际运行状态、覆盖、有效候选和具体结论。可合法不适用的检查须在任务批准时定义 | 故意跳过核心作业、伪造同名状态、前置失败导致未执行时不能进入发布 |
| H09 | 不可信候选的构建脚本拿到高权限密钥或共享缓存 | 不可信构建无发布凭据；高权限阶段仅处理受控的不可执行结果和独立检查，不能执行候选提供的 shell、Action、缓存脚本。私有库保护不可用时只承认审计模式 | 恶意构建过程取不到发布凭据；若现实身份可以绕过，报告保护未成立 |
| H10 | 自洽的哈希包可以完整伪造没有发生过的动作 | 原始采集须绑定实际进程/宿主/页面、动作与后置状态、候选身份；独立审查可访问原始观察。哈希只证明字节，不能证明真实性 | 协同伪造合同+JSON+摘要但没有实际动作，不得获得真实运行通过 |
| H11 | 每改一版就重跑 fixture、完整审查和 GPT Work，越跑越费 | 失败机制与预算绑定原任务，不以新 SHA 清零；廉价回归可迭代，昂贵真实验收只在稳定候选；同因无新证据停止重复模型调用，转根因归因 | 同一缺陷反复自评不生成多轮完整审查，新的有效修复仍能被验证 |
| H12 | 建新框架拖住 Lucerna；VibeResearch 状态与 Bridge 被重新造一遍 | 不为统一名称复制科研 Slurm、队列/周期状态，也不再造 Bridge 状态机。先接当前产品现有入口；只有第二个平台证明共同缺口才抽象代码 | 普通小修不要求常驻服务/新数据库；新平台接入仅新增适配器 |
| H13 | 工具自检 exit 0、报告非空被冒充完整用户能力 | 结果保留证明类别：结构、单元/受控逻辑、真实行为、真实宿主/平台、独立产品审查、实际发布；汇总只能声明证据所证明范围 | Lucerna 自测/GAP、Bobbio 非空包、Mica bundle 校验不得替代正式用户动作 |
| H14 | 风险分流只按改动文件，漏掉完整任务依赖；或小修全量过重 | 选择器取完整用户路径依赖闭包、受影响旧行为、相关历史事故、交付目标要求，再合并重复检查。设计/领域模型负责真正的依赖语义，程序核对实际执行集合 | 改问卷必须能从正常注册进入；改小文案不能自动触发所有设备与审查 |
| H15 | 禁用主功能、全部降为未知或手动退路就通过“安全” | 安全不破坏与新增能力确实有用两个独立正面检查；未配置/延期不能被写成已完成。退路可合法存在但不冒充主功能 | Mica 默认关掉、高亮不工作、Lucerna 未配置假称已接入都不能完成所承诺能力 |
| H16 | 一直针对已见 fixture 调整，同类新输入仍失败 | 历史失败进入廉价开发回归；冻结最终候选后用代表性变化输入/状态序列和独立观察评估，禁止无限追加、挑一次绿色 | 改节点数、长文本、不同屏幕、用户状态族应仍满足本轮承诺；失败不能改样本冒充未见 |
| H17 | 私人真数据需要验证，但直接外发会泄密；脱敏过度又丢失布局问题 | 受限本机保留真数据运行收据与私有原始材料，外发仅最小脱敏派生；派生保留关键形态并注明证明范围，不能冒称看到真账号 | 外发无私密主机/凭据；长文密度等性质脱敏不能改变其难度 |
| H18 | “246条全部映射”误当所有历史已穷尽及机制已生效 | 继续补每个仓库原始审查/工作流事故/用户反馈；区分已修历史、当前源码缺口、产品边界和待验证需求；控制必须在正常入口真实执行才称有效 | 新发现同根因更新旧控制，确实新根因补条目；不制造“全部已解决”百分比 |
| H19 | 仅修验收器或报告就反复重建/重装产品 | 区分产品运行提交/包 P、不可变原始观察 E、交接 H、回执 R 及独立验收器版本；影响分析后只重跑受影响部分 | 同包仅修报告不重装，观测器失真需重采相关事实，真包改变才重新审必要产品场景 |
| H20 | 会话保存被误当机器和执行进程持续在线，断网后重复安装/票据消耗 | 复用 Bridge 的真正运行寿命/外部等待；恢复核对进程、Git、当前资源、外部动作和原授权。结果未知的副作用先查后置状态，不能重发 | 进程断开后不会虚报后台推进，已有正确版本与已消费票据不能重复操作 |

## 三、三个绝对不能互代的交付事实

一是完整用户功能实际可操作，且旧能力没有退化。二是对应证据与专业审查确实证明了该版本的产品质量。三是用户真实使用的安装或部署目标确实是这个版本。一个提交、一个脚本 PASS、一个 GPT Work 结果都不能同时替代三项。

没有真服务账号、目标浏览器身份、设备或安全审查环境时，相关结论保持未验证；不牵涉该资源的安全后台工作继续进行。

## 四、技术形态的证据条件

TypeScript/官方 Codex SDK 是候选工具，不是规定所有项目必须迁移 JavaScript。SDK 支持启动/恢复会话和事件，不证明目标主机安装版本、订阅/费用及合法权限。对 Reviewed/Control 优先消费现有角色运行器；对 Lite 小任务不额外造机器常驻状态。只有重复的跨项目产品准入和证据消费获得实测，才给研工台独立运行包长期分发地位。
