# 研工台 v0.5：复杂产物交付流程的完整重做稿

2026-10-13。**当前是已写入GitHub、可核查的设计与事故归因，不是已经部署的生产系统。** 用户尚未认可方向；本轮不准备或运行Critic，不修改六产品、CARE、Bridge或插件，不启动训练/付费模型/用户设备操作。Notion不承载本轮方案，此前误写草稿正文已清空，原空目标页保留。

## 一、最终建议建立什么

**研工台是独立版本化的任务运行包，负责同一个复杂产物从需求、专业设计、实现、真实检查、内部返修到交付和规则维护。** 软件、网页、模型与统计/科研产物共用这条责任链，领域语义和具体检查留在各项目。它不只是文档/插件，不只是最终验收，也不先建新聊天界面、数据库或常驻调度平台。

正常运行在用户已授权的真实开发机。它实际派发专业阶段、主Codex及必要的只读审查，并调用项目已有观察脚本；用户不用每轮重新给角色发提示词。没有合法可用的执行主机、模型或权限，任务停在可恢复的真实状态，不能用“会自动继续”掩盖缺入口。

| 组成 | 它必须真正执行的动作 | 不能重复制造的东西 |
|---|---|---|
| 任务适配 | 识别有效Goal、当前已有成果、不可被缩小的用户/科学义务和变更影响 | 不复制项目原要求或Bridge CURRENT |
| 专业与执行派发 | 解析实际安装的Skill，明确启动设计/文案/领域阶段；启动主实现和必要独立审查 | 不把Goal中“请调用插件”当已调用；不造多个竞争Controller |
| 独立观察与准入 | 运行正常用户入口、独立参考与受保护最终检查，区分结构/受控/真实/专业/交付证据 | 不重新写所有平台测试；不信实施者自报或同源假指标 |
| 恢复与维护 | 错误回正确owner、避免重发外部动作，自动触发AGENTS整理/迁移/退休及加载回归 | 不把一次工具失败升级为用户科学决策，不每次全量重验 |

**插件管专业方法；Bridge管执行权限、工作树、已安装模式的角色/恢复；项目管原始要求、实际程序与测试；研工台管这些能力是否被同一任务的正常入口真正消费。** 已有Reviewed/Control时严格映射其现有角色，不偷塞第六个Verifier/新CURRENT。普通小任务保持轻量，有重大科学/安全/发行风险才使用相应更强边界。

## 二、这一轮与前版最重要的不同

### 1. CARE不再只有Route B的12步

[模型谱系与事故归因](CARE_LINEAGE_AND_CAUSAL_AUDIT.md)已沿基线、SRR各代和生产Batch、Cascade/SER/DG/DPR/ARC/PRISM、MyoPath/MyoWall/QIF、四lane、ASE与develop多角色流程继续追查。原40项保留，本轮补上此前漏掉的大量中间路径和验收/控制器自身故障。

例如：Route B连续阶段只检查上一阶段令牌却fresh初始化；B6用固定随机小张量训练，验证事件只是计数，逐病例Dice由idx和阳性flag生成。PRISM四尺度算出但最终只用level0，anatomy decoder实为1×1，正式数据只有synthetic，部分loss占位。MMRD真实训练也仍可能有推理/空间恢复/teacher增强错配。复杂Agent-Flow后来仍暴露Verifier新增无依据阈值、loss归约漏检和报告身份导致反复重验。

本轮实际执行了B6的纯函数反例：完美预测与全空预测得到同一0.435，真实Dice参考分别1与0；同一病例换列表位置又变0.445。原函数标为proxy，因此不冒称它伪造官方分数；它不能完成真实逐病例评价，这一点已有直接可复现证据。

### 2. 核心门槛前移到“实际实现形成后、大成本投入前”

Planner/Critic只能审当时的方案，不能预先验证尚未写出的loss参数、数据loader或真实按钮。新流程在第一条正式路径能运行时核对原要求到实际消费者，再决定能否铺开UI或进入长训练。后面仍有完整回归与独立候选验收，但不再等大成本已经花完才发现核心被换成低配实现。

### 3. 主实现可用子代理，独立验收由外层真实派发

主Codex作为集成负责人，可并行有限、不冲突的代码/测试任务；它不是被要求独自写一切。独立审查不属于这些开发子代理，由任务运行器在正确阶段启动新上下文、只读候选并读取原始要求和独立观察。Review/Control中的该职责由已有合法角色承担，不额外加平行审批。

每个审查阶段以集中发现、一次修复、一次受影响复核为默认有界安排；代码错误归Executor，观测器错误归测试owner，要求解释归Planner，只有实质新取舍/权限/费用才需要用户。已有Bridge更严格的人类出口不会被外层循环绕过。

### 4. 验收标准公开，受保护判定和未见样本分开

[验收时序与隔离](GATE_TIMELINE_AND_ISOLATION.md)明确T0–T6。实施前知道“必须实现什么”是正确的，不需要把全部测试藏起来。验收职责先从原要求形成独立参考和判定；开发者可用公开回归；候选固定后由独立端生成事前规则允许的新输入。后加检查区分补原义务测量、接口修复和真正新标准，不让Reviewer照实现改答案。

隔离是实际账户/目录/工具/凭据边界，不是换文件夹或另开会话。不能复制实现helper做独立oracle，不能在候选可改的同一目录放最终标准再宣称防绕过。

### 5. AGENTS成为开发收口责任，不再要求用户维护

[AGENTS生命周期](AGENTS_LIFECYCLE.md)写明触发点、维护调用、保留/更新/合并/下移/退休/归档及审批。旧规则已存在却复发时，先修真实调用/权限/检查器，不再追加同义警告。实际入口改变、规则冲突/超出加载预算或阶段收口时自动检查；非语义整理在一次性授权范围内正常处理，权限/科学目标变化不能自动放宽。

规则提交后还要验证真实指令链、override/作用域、加载上限和旧会话是否仍持有旧指令。读过文件不等行为已改变，需要正常任务和反例回归。

## 四、Lucerna例子说明的不是又一次截图研究

完整实例以现有真实Cloudflare R2读取增加容量提醒说明：主实现管理纯阈值/去重与UI文案子任务，自己集成提供方、共享状态、通知与持久化；首条真实链验证缺值/失败不是零、子服务到顶部一致；开发期完成取消/隐藏/重开、秘密清理、重复通知和旧提供方回归。内部真实操作与完整画面合格后才到GPT Work，不让它第一轮发现按钮/状态/假数据错误。

截图只使用已有捕获和同次运行脚本，在获准专用会话中批量采必要场景。采集、传输、审查分开；传输坏了不重构产品，报告修了不重装。Bobbio复用同一基础边界，但真实Zotero往返/资料隔离仍走自己的脚本。Asteria第一幅可操作图就看整体节点—关系设计，CUHK文案在第一轮真实浏览时检查，不等用户提醒。

## 五、当前能相信什么，不能相信什么

现在有的是：实际可读的GitHub提案、逐项因果与来源、明确的调用/权限/时序/维护合同，以及一次新增历史源码局部反证。**没有的是：新运行包已经在六仓库和CARE正常入口全部接通的证据。** 本轮没有执行独立模型审查、真实GPU/用户桌面/登录态或正式发布，不能承诺所有未来未知缺陷永不出现。

原始历史还未全穷尽，尤其MLoRA/FSCF个别复现、早期M0–M7及Batch0–6逐run与部分私有材料。它们已具体登记为补证缺口；不因为写了40项或246项就说“全部事故已经调查完”。已有来源能明确支持的失败已逐项归因，科学负结果和获准停止没有被硬说成降级。

真正证明路线有效，要同时满足：历史坏实现被同一正式入口拒绝，正确完整实现能交付，规则更新被实际消费，小任务不背全套成本，普通代码/测试/截图错误不再首先交给用户。若这些做不到，应修真实消费者或收缩/改变路线，而不是再以一次方案审查PASS结束讨论。
