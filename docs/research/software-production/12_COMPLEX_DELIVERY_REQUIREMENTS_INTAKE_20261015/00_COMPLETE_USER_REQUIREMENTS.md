# 复杂任务自动交付系统：完整用户需求与验收合同（归档候选，不是已批准架构）

更新时间：2026-10-15。对象：用户要求的长期复杂任务自动交付系统，产品名 KeelArc 仅为暂名。此文件将要求转成可审查的系统能力；技术选型、仓库归属、具体版本、任务运行权限均未批准。**绝不把用户想要的体验描述成已经具备的实现。**

## 0. 用户真正要什么

用户日常主要从 Windows Codex App 或服务器 Codex 直接交代任务。真正需要的是：一次明确产品/科研目标，系统在正常执行入口实际发现和阻止历史已知的缩水、伪完成、审查失灵、反复测试、资源浪费等问题，自动完成合法范围内的修复和交付；用户能实时查清每个组件究竟有没有起作用；仅在改变产品/科学方向、合法权限、费用、不可逆影响时需要用户决定。产品必须显著缩短六软件、CARE、未来 Shione/深度学习和科研复杂成果的实际交付周期。

用户不能接受“多写规范”“多一个 Skill”“增加一轮审查”“多一层薄封装”“多一个状态机”却没有真实净收益。系统本身是复杂软件，必须在真实入口自我使用、自我观察，并经独立真实验收。

## 1. 所有复杂任务接入、普通修改成本低

- REQ-001【必须】：软件、网站、原生桌面、安卓、浏览器扩展、深度学习训练/评价、统计科研复杂产物、科学报告与未来新项目，应有统一的受管交付能力。统一的是入口与可验证责任，不是强迫所有项目采用同样验证手段。
- REQ-002【必须】：从用户熟悉的 Windows Codex App 和服务器 Codex 发送任务时，明确精确介入点；不允许默认用户搬运提示词、重复整理分支、上传 ZIP 或手工创建长任务。
- REQ-003【必须】：区分一般咨询、小修、完整功能、高成本/敏感实验；小修不默认被迫使用全部审查、独立机器、GPU、GPT Work 或高费用模型。
- REQ-004【必须】：复杂任务的接入不可仅靠主 Codex 自觉阅读规则；需证明正常入口真实调用及绕过条件。
- REQ-005【必须】：系统可接入新项目，如 Shione、其他深度学习模型或科研项目，适配时不得重新建任务管理器、复制整个验证器体系或改动不相关项目源码。
- REQ-006【必须】：记录首次接入成本、每次任务额外操作/时长、额外调用成本，并与完全不建新系统的基线对照；净收益不成立时取消或收缩相关通用功能。

## 2. Codex 的真实介入与任务完成权

- REQ-007【必须】：Windows Codex App：用户按原习惯发送任务后，实际由哪一个可用钩子、原生功能或受管入口收到任务、能否合法启动另一个会话、是否造成双重执行，必须在实机验证。不得把“钩子出现”直接等同“完整会话控制权”。
- REQ-008【必须】：服务器：识别正确的项目、分支、工作树、Codex 身份和 CODEX_HOME；不能把工作目录误当成 Codex 身份，不得混用 Longleaf 的 USERS 与 OVERFLOW 命名空间。
- REQ-009【必须】：每个受管任务只有一个当前任务状态/推进权威。若任务已归 Bridge Reviewed/Control，其规则与合法阶段不能被新工具暗中覆盖；独立产品若接管执行必须说明与既有所有权的交换条件。
- REQ-010【必须】：清楚区分 Codex 回答“完成”、开发测试通过、独立真实检查通过、正式交付/科研结题；不得用第一个代替后几个。
- REQ-011【必须】：Codex 自称完成但实际有问题时，必须说明哪一个实际程序触发检查、从哪里拿到原合同和同候选产物、如何产生可复核失败、怎样把确切问题交回原合法任务继续修复、由谁复查；不能只有“再找另一个 Reviewer”。
- REQ-012【必须】：编码前、首条真实纵向链、Codex 准备停止、最终验收、正式发布/昂贵训练前，各关键介入点均需注明触发者、输入、判断依据、干预权与不可干预情形。
- REQ-013【必须】：自动继续须保留会话/工作树/提交/产物身份；原生会话不可控制时如实陈述用户需要的最小交接，不能冒称无缝。
- REQ-014【必须】：主 Codex 负责集成；子代理仅在真正隔离、不冲突且节省成本时使用；不能因为复杂任务便默认扩大角色数量、并发或模型调用。
- REQ-015【必须】：Reviewed 早期检查不可冒充正式独立 Review；正式状态及最多允许轮次由其已有合同管理；科学 Control 的 Verifier 权限与任务预算不得被新角色复制或重置。
- REQ-016【必须】：在真正独立审查未运行、实际观察缺失、版本不一致、权限不成立时，显示未证明，不得自动放行。

## 3. 严防缩水、假数据与旧能力退化

- REQ-017【必须】：先从用户实际消费对象形成正面成功义务：做成后有什么真实行为、模型能力、论文结论或可用交互；不允许实现者换一个容易通过的目标。
- REQ-018【必须】：第一条真实生产链必须在全面开发或昂贵运行前由正式入口执行、观察，不得长期停在模拟环境或“快写完了”。
- REQ-019【必须】：模拟数据、夹具、替身服务可以用于开发和有界回归，但要和真实用户/数据声明隔离；不能无限刷新夹具、靠重复绿灯冒充新能力。
- REQ-020【必须】：深度学习必须检查当前批准的模型结构、输入/数据划分、采样、前向、损失、梯度、优化器、阶段权重接续、预测、医学指标；单次随机张量与自造代理指标不能升格正式结果。
- REQ-021【必须】：旧功能、旧交互、已有设计、真实数据语义、公式、隐私边界必须在相关改动中受影响范围回归；不相关的完整大测试不能机械重复。
- REQ-022【必须】：识别执行者同轮修改验收代码/参考、清空严重错误指标、换较易路径、关闭主功能来制造安全或通过；同一错误必须有正例/坏例/缺证据反例，不得只拦错误代码特征。
- REQ-023【必须】：历史已修问题不能未经当前候选实测称仍在；历史风险不能自动写成实际事故；科学合理 NO_GO 是合法结果，不能被迫训练到正面成绩。
- REQ-024【必须】：不允许最后才发现平台根本不可达、需要真实权限或缺少专业来源；在风险进入昂贵阶段前先检查环境和合法运行入口。

## 4. 独立专业审查、真实可消费产物

- REQ-025【必须】：真正审查所需的完整原设计、Figma、源码/数据/论文、整屏渲染、真实运行包、设备动作、输出和原始指标必须提供给有权限的审查者；只看开发者摘要不得宣布合格。
- REQ-026【必须】：审查器按领域和实际任务族准入。必须评估漏检、误拒、正确弃权和样本来源；STAT5060 审查器在 50 页中只发现 10 个坏例中的 2 个，是必须防止复发的反例。
- REQ-027【必须】：测试程序出错、审查者误判、产品缺陷、环境/权限问题、科研 NO_GO 分开归因；不得以验收器错误逼正确产品改错。
- REQ-028【必须】：真实 UI 需遵循项目实际 Figma / 设计系统、整屏信息层级、响应与可读性；不能用结构/截图存在/像素阈值取代审美和实际操作。
- REQ-029【必须】：面向用户的中文必须自然流畅，避免项目内部英文流程词和机器状态直接暴露；检查真实页面/长文本/整体语义，而非仅用禁词或词表扫描。
- REQ-030【必须】：文档、PPT、PDF、论文、科学图以用户实际消费对象验收：完整渲染、数学/统计/科学含义、可编辑性、源保真、可追溯引用及最终文件身份。
- REQ-031【必须】：最终同一候选的源码、构建、已安装/已部署目标、运行过程、观察器与产物对应；旧截图、别的构建、空 CSV、仅哈希、仅回执不能构成交付证据。
- REQ-032【必须】：审查结论不得凭临时提高阈值、增加未经批准的科研/产品要求来无限返修；阻塞项要有原合同、事实证据、因果风险和最小关闭条件。

## 5. Slurm、远程持续执行、失败恢复

- REQ-033【必须】：区分账号与 GPU 申请权限、命令前置检查、计算节点真实运行、作业队列等待和科学训练成功；不能因为已提交 sbatch 就宣布完成。
- REQ-034【必须】：Slurm 排队状态应由真实调度器和低成本监测器持有，空等时不得占用 Codex 反复轮询；有效任务待资源时保持任务身份与可继续路径。
- REQ-035【必须】：诊断排队原因：正常 Priority/Resources、无效 QOS/账号/分区、依赖不可能满足、集群停机分别处理；不允许所有 pending 都等固定24小时，也不能一 pending 就 BLOCK。
- REQ-036【必须】：CARE 现有专业规则包括 htzhulab、a100-gpu、volta-gpu 的兼容路由、分区竞争及 2 小时×12 次 all-pending 判断；只能在其合法适用范围复用，不能变跨项目通用硬编码。
- REQ-037【必须】：如可竞争多个队列，必须先确认项目科学等价、算力兼容、镜像输出隔离/幂等锁、并发预算、对自己作业的取消权限；不能未经合法授权在多分区重复提交。
- REQ-038【必须】：节点抢占、超时、环境导入失败、输出缺失、任务记账延迟、断网、调度系统不可达须有分流：同范围修复/保留等待/正确升级决策；不能机械再训。
- REQ-039【必须】：Longleaf 正确使用项目自己的完整 Slurm 清单视图（如现有 sq），不得仅凭 squeue -u 当前默认视图判断实验不存在。
- REQ-040【必须】：明确 GPU/CPU/内存、时限、作业次数、实际令牌/时间计量可得范围；费用和追加资源由实际受权入口控制，非 README 或模型自述。
- REQ-041【必须】：若作业到达终态，需真实 finalizer/collector/聚合后置行为、checkpoint 与预测/GT，才可进入科学或产品审查；缺证据不能记成功。
- REQ-042【必须】：当前既有 Longleaf Access/Bridge A/B/Tailscale 运行时不得因新工具测试被无权限停止、取消、重启或改变远端路径；研工台恢复必须区分自身任务与远程访问基础设施。

## 6. 规则、专业能力、质量和用户成本

- REQ-043【必须】：每项真正需要的 Skill/Plugin 必须被正常执行者发现、实际加载、调用并对结果产生可核验影响；声明“已调用”不算。
- REQ-044【必须】：AGENTS、源合同与专业规则在长项目里能维护：重复合并、过时迁移、能力替换和 README 同步；已存在规则但未执行时优先修消费入口，不堆同义规则；关键权限/安全/科学语义不可擅自删除。
- REQ-045【必须】：一次合法任务、资源、账号与范围授权不能反复要求用户确认；超出范围或不可逆变化必须重新授权，不得借回退命令偷换。
- REQ-046【必须】：能够识别并减少无意义的重复测试、全量安装、桌面前台干扰、GPU 实验、同类审查、无进展模型调用及启动多个不必要子代理；不能只把成本问题换成持续监视器成本。
- REQ-047【必须】：真实缺陷在既有任务/预算内有界返修；检测器、报告、证据传输故障只作必要局部修复；无论 WAIT 还是 BLOCK 都须保存可恢复进度及下一步，不用新增任务号重置预算。
- REQ-048【必须】：GPT Work/用户不应成为第一个发现明显 P1 的一线质量检查员。需要用户首次看产品时应提供已内部自检的稳定候选和明确尚未证明的范围。
- REQ-049【必须】：持续比较新系统与项目现有入口在实际用户介入、完成时间、错误率、额度/费用、安装维护成本上的净效果。不存在“文档通过即证明有收益”。

## 7. 可视化、可检查每个组件的真实作用

- REQ-050【必须】：提供用户可以实际打开的可视化控制台或等价入口；能够查所有任务当前权威状态、活动/等待/失败原因、最终候选和真实下一步。
- REQ-051【必须】：每个组件显示实际触发的事件、输入来源、运行代码身份、输出证据、费用/时长及未调用理由。已安装、代码存在、状态文件存在不能显示“能力正常”。
- REQ-052【必须】：区分诊断性观察、独立专业判断、真正受保护强制；未具合法隔离只能报告观察，不能虚报无法绕过。
- REQ-053【必须】：能展开查看事件时间线、实际终端/程序记录、候选、源、专业报告、失败归因、反证和返修记录；面向用户首先用自然中文说明实际情况，不堆机器状态与路径。
- REQ-054【必须】：实时事件日志不等于第二套会推进任务的 CURRENT。任何独立可视化必须从真实权威状态、执行记录和观察器来源派生，不能让状态错位。
- REQ-055【必须】：日志与证据不应泄露凭据、用户私有浏览器会话、医学数据、真实身份或令牌；采集最小化且权限受限。
- REQ-056【必须】：控制台离线、掉线、重启后必须可靠恢复查看和合法继续；组件失效或事件缺失不能静默显示绿灯。

## 8. 七个现有项目和新领域

- REQ-P-LUC：Lucerna 覆盖 Windows 原生托盘/窗口/通知、凭据/状态聚合、隐藏/恢复/关闭/重新安装/启动项、真实 Provider→聚合→首屏；用户桌面副作用必须隔离；不能为了验证刷真实前台或只用假 headline。
- REQ-P-BOB：Bobbio 覆盖真正 Figma、Reader 与 Zotero profile/dataDir、系统 URL 处理器、更新缓存、注释往返与用户隐私副作用；PreflightOnly 标签不能免除实际 -Apply 链审查。
- REQ-P-MIC：Mica 覆盖当前真实 ChatGPT 宿主、有效扩展安装包、原生编辑无损伤和高亮实际收益、长会话/低内存/PDF 选择；不允许关闭主功能冒充安全。
- REQ-P-SEM：SeminarArc 覆盖真实 APK、Android 系统选择器、照片/OCR/音频/Room/导出、真设备身份、错误选择器校准；压力测试事件次数不能代替真实用户能力。
- REQ-P-AST：Asteria 覆盖实际浏览器 SVG/DOM 几何、长关系层级、连续交互、数学/科学可读性；交叉数恒零、缺测当零和测试通过却难看的整屏须被识别。
- REQ-P-CUH：CUHK_Date 覆盖可见表单注册/422/password、不同身份/一次性票据、问卷、重入、托管隐私、简繁中文自然阅读；直接接口成功不是浏览器表单成功。
- REQ-P-CARE：CARE 覆盖所有原40条和追加52条所涉及的架构缩水、伪数据、损失/梯度、模态与尺度、权重接续、切分、空间推理、B6代理评分、DG/ASE/MMRD/PRISM、Slurm 调度/账号/合法科学停止。尚未取到的旧附件不可假称穷尽。
- REQ-P-NEW：未来 Shione、其他医学/生信/统计科研等必须走领域适配与真实质量验收；语言教学、语音、交互、科学证明等不得被万能 UI/CI 检查替代。

## 9. 研工台自身的质量、自举及架构选择诚信

- REQ-057【必须】：研工台本身是复杂软件，需有实际产品设计（必要时 Figma）、自然中文、真实全屏、交互与响应式、可访问性、事件可信性；不能做出另一个 Lucerna/Mica。
- REQ-058【必须】：首个可运行版本能在自己真实入口发起有界开发任务，记录真实 Codex 事件，恢复现场，证明开发—独立验证—返修链，而非用写死模拟状态。
- REQ-059【必须】：自我开发和测试不能自我签发最高等级独立 PASS；外部可信观察器与最终候选身份必须独立。
- REQ-060【必须】：比较至少五条现实路线：仅修项目自身+现有机制、Bridge 最窄扩展、Skills 本地能力方案、独立有运行权产品、成熟编排/代理实现及其组合；不得预设必须新建仓库、必有中央控制台或必须使用钩子。
- REQ-061【必须】：研究者必须给出代码级正常入口、事件、受权动作、失败分支及可证伪探针；不同路线同任务样本比较，拒绝通过换测试、扩指标或删除旧要求取得假胜利。
- REQ-062【必须】：独立研究与审查阶段只许取证、写研究档案；未有有效 Critic PASS 与用户明确授权，不启动 Windows 真桌面、Slurm/付费实验、产品实现、新工作流/服务或发布。
- REQ-063【必须】：所有既有用户要求、六仓246 + 晚期25 + CARE40 + 追加52（363条登记，不等于363次独立事故）、历史21问、三位 Critic 的7+12+2阻塞与本线程新增要求必须有可追踪索引；未复核和未验证必须明确标注。
