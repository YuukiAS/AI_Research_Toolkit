## B. 本次续接后提取的12项问题（只保留提问）

- **N01**：2026-10-14 用户明确要求所有复杂交付强制接入、覆盖 CARE + 六仓全部失败，适配不能显著延迟开发；目标是省心而非叠加流程。
- **N02**：到底要开发哪一种真正可运行的产品，而不是又写抽象的流程层和检查函数？
- **N03**：我在 Windows Codex App / Longleaf 服务器上直接发送提示词，系统具体通过何种可用入口介入、是否双执行、什么时候取得控制权？
- **N04**：Codex 已自称交付，真实还有缺陷时，由哪一个实际程序发现、谁持权重新唤起 Codex、如何保留同候选和合法 Review？
- **N05**：必须能从真实事件、日志及可视化界面看到每个组件是否发挥作用，不能只有自报运行状态。
- **N06**：是否在 Toolkit、AI Skills、Bridge 或新仓库开发？不能先定仓库再找理由；若独立产品必须自己真实使用及经过美学/文案验收。
- **N07**：深度学习任务究竟谁能 sbatch；Slurm 长排队、无效 QOS、抢占、结果缺失、通道断线如何分类、等待、恢复、告警，不烧 Codex 额度、不频繁要求用户确认？
- **N08**：为什么凭什么相信最新架构最优？不接受每提一个新要求便整个推翻，必须独立比较真实替代并预先证伪关键假设。
- **N09**：要先看完整且可检验的 GitHub 文档，不要一份 Prompt/ZIP 就让用户发给 GPT Pro；历史线程要求、事故、三份 Critic、遗漏都要记录。
- **N10**：要把‘统一软件开发流程’旧线程全部承接；包括既有四卷、原21问、14阶段12场景、曾要求三十条以上 CARE 机制降级、主要运行者/子代理/独立审查/规则维护/首次用户验收。
- **N11**：用户明确不接受：首次复杂开发就丢给 GPT Work/用户找明显 P1；反复刷 fixture；开发还在假数据；重复验收；一有问题 BLOCK；浪费额度；需要手动同步看板。
- **N12**：正式科研可能得出合法 NO_GO；错误审查不得强迫模型改错；权限与费用审批需要实际有效而不是规范假批准。
