## 1. 独立判断的起点

真正缺少的不是又一套任务状态名称，而是三条能在实际入口成立的连接：

1. 用户的要求与当前执行身份相连：谁拥有哪个任务、会话、仓库、候选和资源授权。
2. 声称完成与真实消费者相连：可见窗口、真实账号流程、宿主扩展、原生批注、科研输出是否消费了那份实现。
3. 发现问题与合法返修相连：原执行者在范围内继续，工具/检查器错误转给相应负责人，科学负结果不被当成程序错误无限修。

十仓库已有大量测试、专业约束、controller和finalizer。共同失败既包括缺调用，也包括调用了错误检查器、验收对象不是用户使用对象、质量判断本身不可靠。任何路线都必须同时比较控制可靠性与验收有效性，不能只展示更多回执。

## 2. 已核实的硬事实

- AI Skills 的 workflow-core 主要是技能内容与路由配置；字符串单测不证明每次实际消费。Bridge Reviewed 的当前 main 和 release 都使用 fresh `codex exec`，记录 thread_id=None。继续同一仓库任务不等于继续原App会话。
- 当前[Codex配置](https://learn.chatgpt.com/docs/config-file/config-basic)将hooks/goals列为Stable；[同步Stop](https://learn.chatgpt.com/docs/hooks)可要求继续。后台hook不唤醒idle，并不负责会话退出后的持久续办。不能沿用“所有hooks都实验”或“插件天然是全局控制器”的假设。
- [App Server](https://learn.chatgpt.com/docs/app-server)公开精确thread恢复、turn输入与事件；SDK支持按id恢复。它们没有证明第二进程可无冲突接管一个已打开的Windows App任务，目标宿主仍需探针。
- Lucerna的governance报告可以PARTIAL而exit0；Asteria当前RC19脚本有写死的零指标。把进程exit、CI颜色或producer PASS当产品验收，可能系统性错误。
- Bobbio必须区分Zotero profile与data directory；Mica 0.4.1候选与main 0.1.7的能力不同；SeminarArc的local-safe provider foundation不是live ASR。
- CARE已有执行验证完成且科学NO_GO的结果；checkpoint、充分训练、真实机制贡献和最终科学判断不是同一个门槛。

## 3. 候选A：完全不建通用系统，只修现有入口

**形态。** 将钱和时间投入项目真实验收与现有Bridge/CARE闭环，减少重复说明和失效测试；不加公共运行服务或全局完成拦截。

| 维度 | 具体做法与限制 |
|---|---|
| Windows / 服务器入口 | 用户仍直接在现有Codex发消息；现有任务协议由当前agent消费。未获得原入口生命周期能力时，诚实保留用户继续一次的成本。 |
| 假完成返修 | 优先修false-green脚本，绑定candidate、真实入口和最终消费者；当前agent内自审，已有外部review由既有owner接回。agent已退出且无owner时不承诺自动续办。 |
| Slurm | CARE沿用自己的controller/finalizer/terminal accounting；普通项目不引入HPC抽象。 |
| 专业质量 | Figma/整窗、香港繁体、真实宿主、Android硬件和科学机制各归项目，复用成熟测试工具。 |
| 观察 | 在已有result/日志中统一显示缺证与真实完成分量，必要时导出标准trace；无第二完成状态。 |
| 新项目成本 | 仍需一个真实纵向验收入口、关键反例与权限说明；公共代码成本最低，重复接线成本可能较高。 |

**未证假设。** 项目局部修复能消除多数用户返工；跨会话断裂并非主要剩余成本。
**保留/淘汰条件。** 若同一冻结任务集下，局部修复已使用户介入和漏检明显减少，A应获胜。若反复在结束/恢复处丢失责任，且额外公共接线能实测减少该损失，A不再充分，但其专业验收仍作为其他路线底座。
**公平成本。** 不能把A定义成维持所有已知错误不修，然后让新系统与坏基线竞争。

## 4. 候选B：原入口内的可选完成检查与续办适配

**形态。** 在既有AI Skills/Bridge的职责边界内加小型集成：同步Stop检查当前任务的真实验收结果，发现明确且有授权的缺口时把理由送回同一任务；长等待交给已经拥有任务的持久owner。无需新产品仓库和中央任务数据库。

| 维度 | 具体做法与限制 |
|---|---|
| Windows / 服务器入口 | 正常发消息不变；一次性安装/信任后由受支持宿主加载hook。Windows App、服务器CLI、远程App分别验证，不能一测代三测。 |
| 假完成返修 | Stop只接收有来源的失败/缺证及精确task/candidate身份；同步继续原任务。外部独立review回来较晚时，仅经已验证的精确线程适配器或既有owner处理。用户中断优先。 |
| Slurm | 排队让模型停止推理；已有CARE持久finalizer核算与聚合，事件到达后再请求原owner继续。不用Stop空转或异步hook保活。 |
| 专业质量 | hook不判审美/科学真理；调用项目检验与独立评审。检查器失败、来源冲突、产品错误分别处理。 |
| 观察 | 记录触发事件、调用、真实输出、修复及后置验证；状态从既有owner推导。 |
| 新项目成本 | 适配既有acceptance命令和最小身份/权限字段，无完整新DSL；但用户没写清的科学目标不能由hook补造。 |

**未证假设。** 目标安装版本实际触发hook、短返修确实留在原thread、与Goal/用户输入/多个hook不竞态，错误不会被静默当完成。
**淘汰条件。** 需要用户每次手工建task包、无法识别原任务、意外续错线程、越权、无法可靠尊重停止，或公共接线成本超过收益。异步远程返修接管失败时必须删去该承诺，不能换成fresh exec后继续称“原线程”。
**初步评价。** 最值得小探针验证，尚不足直接开工建全系统。配置驱动的最小公共接线与项目私有语义分开。

## 5. 候选C：显式托管执行入口，拥有完整生命周期

**形态。** 用户明确把一项任务交给基于app-server/SDK的受控客户端；该客户端从开始就拥有会话、权限、事件和恢复。可在Bridge内部实现替换入口；真有跨进程持久需求时评估Temporal，而非自造通用可靠队列。

| 维度 | 具体做法与限制 |
|---|---|
| Windows / 服务器入口 | 增加明确的“交给托管执行”动作，客户端记录thread id；不得同时让原App agent和托管agent写同一任务。可用本机或服务器backend，但不能凭SSH别名猜身份。 |
| 假完成返修 | owner从公开事件消费turn完成，运行项目验收/独立review，在精确thread追加返修；权限仍为用户原范围。模型结束不是托管任务结束。 |
| Slurm | owner在持久等待状态让模型休眠；用既有CARE finalizer，或未来明确迁移到Nextflow。必须选择唯一job提交与恢复owner。 |
| 专业质量 | 与A/B相同，不因更可靠编排获得审美和科学正确性。 |
| 观察 | 可直接用事件形成可重建视图，适合统一进度；只读日志不授予操作权。 |
| 新项目成本 | 项目适配之外需维护client、身份、授权、兼容、持久运行和升级；入口摩擦最大风险。 |

**未证假设。** 用户能接受一次显式托管，环境与skills等价；长期故障恢复确有足够频率使运维成本划算。
**淘汰条件。** 成功必须放弃用户的原生直接对话入口，却仍宣称满足原需求；重复agent或重复Slurm写入；新基础设施超过可维护能力。若B原入口不能做而用户不批准变入口，C不可作为偷偷替代。
**成熟替代。** [Temporal](https://docs.temporal.io/workflow-execution)负责持久执行；[Nextflow](https://docs.seqera.io/nextflow/executor)可承担显式科研DAG。二者均不能自行接管App线程或定义科学结论。

## 6. 候选D：外部旁观、独立审查与通知，不自动接管

**形态。** 独立读候选产物、GitHub checks、既有job/result事件，发现矛盾给出精确问题；它不启动第二执行者。可作为低风险小产品或现有报告能力。

| 维度 | 具体做法与限制 |
|---|---|
| Windows / 服务器入口 | 不改变用户发消息方式；只能看被暴露的候选/事件，无法保证看到所有本地未提交工作。 |
| 假完成返修 | 独立发现不等于自动修；通过既有合法owner接回，否则需一次用户动作。不能借“监控”授权发送新命令。 |
| Slurm | 只投影真实队列/会计/产物状态；不提交、取消、改变资源。 |
| 专业质量 | 可做只读视觉/科学审查，但必须有真实artifact访问，不能从摘要猜。 |
| 观察 | [OpenTelemetry](https://opentelemetry.io/docs/concepts/signals/)式trace/log投影；保留UNKNOWN与stale，拒绝自行设DONE。 |
| 新项目成本 | 需artifact暴露与身份映射；没有执行适配，但仍有专业审查成本。 |

**未证假设。** 通知减少盲区且不造成重复打扰；关键本地产物可被最小范围访问。
**淘汰条件。** 仅转发producer自报、看板另造真值、无法落到行动；若目标必须无人干预返修，D只能是组成部分，不能单独满足全目标。

## 7. 共享的检验方法与当前倾向

先修局部验收（A），同时只验证B的最短原入口链。B不能成立时，明确在A/D与需要用户选择入口的C之间决定。此为**实验顺序**，不是事先批准B。

最小共同身份是task、host与Codex身份、thread/turn、repo/ref/candidate、当前owner、授权范围、证据入口。不是要求用户手填这些；能由真实工具取得的由入口自动取得，取得不到必须说明缺口。权限与科学意义不能靠文件hash产生。

所有路线必须面对六种反例：假PASS、错误verifier、真实宿主漂移、重复/乱序事件、未知Slurm状态、充分实验后的科学NO_GO。用同一批任务比较用户动作数、真实漏检、有效返修、总耗时、模型/计算成本和维护量；指标改善前不扩大部署。不把363个历史条目等同当前缺陷或363道门禁。
