# Delivery Assurance：同一架构的 R1 返修候选

用户仍从正常 Codex 入口提出功能请求。拟议系统在写产品前核对原要求，按任务使用成熟能力，保护受影响旧功能；随后运行项目自己的真实验收，把可修失败送回原任务。只有当前成品、独立专业结果和接收回执都成立，七仓各自的最终出口才生成可交付报告。用户不应再负责提醒验收、搬运失败和催促修复。

推荐仍是 **Bridge 既有入口＋workflow-core 小共享库＋七仓原有专业验收**。不增加客户端、常驻调度器、第二任务库、第四工作流或万能评分器。已接受的边界不再提问：受支持正常入口自动接入；受管交付强制验收；Hook 完全缺席时，不保证撤回已经生成的原生聊天错误文字。

独立 Critic R1 的五项意见全部接受，本轮具体补了这些缺口：

- **防止一开始理解漏。** 写前按风险分流；高风险由已有独立角色从原始材料重建要求，原任务消费结果。没有接收者时不假称已自动接上。
- **验收器不能自己批准自己。** 候选先接受冻结好例、坏例、缺证例和旧功能例校准；新专业判断须独立准入。只有批准的准确版本可支持正式交付，首次项目 adapter 同样处理。
- **成熟能力必须真的参与实施。** 合同记录为什么需要、实际版本、如何交给当前执行者、真实读取/调用及对结果的影响；普通后端和文档不误触发完整前端流程。
- **七仓都有确切最终出口。** 文件、函数、命令、专业输入、交付检查、报告和无 owner 恢复均已指定；旧脚本 PASS 绕过检查的负例必须被拒。
- **先验证宿主，再投入公共层。** Windows Desktop、CLI、Remote 的 Hook、同线程恢复、规则加载和取消行为先做无产品副作用探针；关键不支持时先修订入口路线。

这是 **Planner 修订后的实现前送审候选**；固定版本与全包回读状态见 [CURRENT](CURRENT.md)。尚无 R2 独立结论。宿主探针、七仓实际产品验收和安装/加载验证均未执行，七仓 DA enabled 均为 NO。源码和接口设计不能代替这些运行证据。

现行工程估算为全量 **130–316 小时**、首个完整切片 **36–80 小时**，均未量测。首片先做其中 **4–8 小时**的宿主探针，再决定是否进入完整公共层。只增加记录、不能减少漏检或用户搬运时，应收缩回项目 runner 补强；成本不是一次性执行授权。
