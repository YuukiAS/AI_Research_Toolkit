## 02.png

## 03.png

### 新增文字 / 信息

- 第 2 步是调研期只读摘要和 Introduction，用来判断论文是否与方向相关，不在此阶段深挖实验细节，以节省 token 并避免无关信息稀释上下文。
- 10–20 篇文献可直接放入一篇 survey 让 AI 压缩总结；50 篇以上用多级压缩，先单篇总结，每 5 篇一组合并，最后全局总结。一次性全塞进去容易丢细节。

### 图示或结构

- 50+ 文献的层级化压缩：单篇 → 5 篇组 → 全局。

### 与 note.md 的关系

- 重要补充：给出了文献数量阈值和压缩粒度。

## 04.png

### 新增文字 / 信息

- 第 3 步要求核心文献必须由人选。作者将文献调研理解为给 AI 建立领域专家级上下文；深耕某个方向的专家上下文与通用上下文，产出 idea 的质量差距很大。
- 作者警告不要让 AI 自行搜索后直接使用：可能找到与你的主线不匹配的材料，甚至编造不存在的论文；一查审就会暴露。

### 图示或结构

- 人工选核心文献 → 建立领域上下文 → AI 发散。

### 与 note.md 的关系

- `note.md` 未包含“核心文献必须人选”和主线不匹配/虚构文献风险，属于重要补充。

## 05.png

### 新增文字 / 信息

- 第 4 步警告不要直接把 PDF 丢给 AI。AI 处理 PDF 往往依赖 Python 库解析，会发生公式乱码、表格错位和跳行漏段；语言模型读 PDF 时“推断”比例很高，可能漏掉大部分内容。
- 输入质量直接决定后续输出质量。

### 图示或结构

- PDF 直读的风险链：解析错误/缺失 → 上下文不完整 → 后续选题输出不可靠。

### 与 note.md 的关系

- 补充了直读 PDF 的具体错误类型。

## 06.png

### 新增文字 / 信息

- 第 5 步的正确链路是 `PDF → MinerU → Markdown`，再把 Markdown 作为后续任务输入。
- MinerU 可从 PDF 输出 Markdown、LaTeX、HTML、JSON 和图片，保留公式、表格和图片引用。
- 需要机构权限的文献（例如 Springer、Elsevier、知网）可在已登录的浏览器会话中下载，或用 Codex 操作桌面端。
- 材料用 Git 管理，以便追踪原始论文、AI 笔记、中间产出和变更记录。

### 图示或结构

- 文献处理和追溯链：授权下载 → MinerU 转换 → Markdown 输入 → Git 追溯。

### 与 note.md 的关系

- 补充了 MinerU 输出类型、授权下载与 Git 追溯。

## 07.png

### 新增文字 / 信息

- 第 6 步是给 AI 喂结构性空白：idea 应在大量阅读中逐渐“拼”出来。把领域近两年的顶会/顶刊论文 10–20 篇转好为 Markdown，一次性给 AI，要它找“结构性研究空白”。
- 这里的“空白”不是“没人做过”，而是“理论上该做却没人填上的逻辑缺口”。
- 文献质量低时，AI 只能给出普通 idea。

### 图示或结构

- 10–20 篇高质量近作 → 结构性空白识别 → 候选 idea。

### 与 note.md 的关系

- 重要补充：定义了“结构性空白”并给出文献数量。

## 08.png

### 新增文字 / 信息

- 第 7 步是反向挖假设，问“原来的方法为什么会失败？在什么场景下效果会变差？”，而不是正面问“怎么改进现有方法”。
- 作者认为后一问法容易生成“增强特征提取”“引入注意力机制”“融合多模态”等正确但不落地的废话。
- 示例：目标检测不问“如何提升小目标精度”，而问“anchor-based 方法在小目标上失败的根本瓶颈是什么”。先列出低层原因，再逐项检索现有方案是否已解决，剩下未解决的才是候选创新点。

### 图示或结构

- 失败现象 → 根本瓶颈 → 前作逐项核验 → 未解决瓶颈。

### 与 note.md 的关系

- `note.md` 只概括了“问为什么失败”，本页给出完整的反向推理结构和示例。

## 09.png

### 新增文字 / 信息

- 第 8 步是让 AI 扮审稿人挑硬伤。使用一个全新对话，不复用之前生成 idea 的上下文，以避免确认偏差。
- 检查项包括：实验设计是否有漏洞，对比基准是否足够，可控变量是否有遗漏，与现有工作的区别够不够大。至少迭代 2–3 轮。
- 作者认为这些问题在投稿时也会被问；提前用 AI 挑并修正，就是对 idea 的预审。

### 图示或结构

- 独立审稿人会话 → 挑漏洞/对比/变量/区别 → 2–3 轮修正。

### 与 note.md 的关系

- 重要补充：给出了独立会话、审查项和迭代次数。

## 10.png

### 新增文字 / 信息

- 第 9 步的保留标准只有一条：能否设计出明确实验来验证。不能转成可执行的实验，说明 idea 仍太模糊。
- “超越 SOTA 几个点”不是采用一个 idea 的充分依据，因为结果可被故事包装。作者引用“idea 本身没那么重要，重要的是实验探索的发现和结果分析”，并称真正经过探索得到的结果才属于你。

### 图示或结构

- 候选 idea → 可验证实验设计；无法建立此映射就淘汰。

### 与 note.md 的关系

- 补充了保留门槛和作者对 SOTA 数值改善的警惕。

## 11.png

### 新增文字 / 信息

- 作者总结三条可直接采用的原则：
  1. 核心文献由人选，AI 分不清哪些真正重要；论文中“受到 XX 工作启发”的 XX 是创新背书，选错就破坏故事。
  2. PDF 先转 Markdown 再喂 AI，否则 AI 很可能在猜。
  3. “为什么失败”比“怎么改进”更有用；从失败倒推假设，候选 idea 更有故事性且更容易设计实验。

### 图示或结构

- 三条快速采用清单：人选文献、PDF 结构化、失败反推。

### 与 note.md 的关系

- 与 `note.md` 摘要一致，但更精确地保留了原则和理由。
