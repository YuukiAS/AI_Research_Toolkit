## 02.png

### 新增文字 / 信息
图片内对 Idea2Paper 的说明比右侧帖文更具体：核心子模块 `Idea2Story` 建立在知识驱动、可审计评审和自动化精炼三点之上。知识驱动部分使用 ICLR 会议数据构建知识图谱，将概念、方法、领域、论文等实体及其关系用于检索；可审计评审以带真实评审分数的论文为参照，输出较确定的评分；自动精炼使用检索增强与智能执行来强化研究故事的新颖性。

输出不是论文正文，而是结构化文件：`final_story.json` 保存标题、摘要、问题、方法、贡献、实验设计等研究故事；`pipeline_result.json` 保存流水线轨迹、评审、修正等；日志目录保存每次运行的结构化记录。图片称当前能力聚焦“灵感/想法 → 研究故事草案”前端环节。

**冲突：**同一张截图右侧正文把 Idea2Paper 描述为“自动查文献、自动写代码跑实验、画图+LaTeX排版”，而左侧项目说明明确输出结构化研究故事、不是直接论文正文，并把方法开发、实验执行和论文写作放在后续链条。无法仅凭截图判断哪一侧更准确，证据包保留此冲突。

## 03.png

### 新增文字 / 信息
ARIS 被描述为基于 Claude Code 的开源端到端科研框架，目标是在最少人工干预下完成“文献综述 → idea 生成 → 实验执行 → 论文撰写 → rebuttal 应对”等流程。核心架构是 `Executor–Reviewer` 双模型对抗：executor 负责代码、写文稿、跑实验；独立 reviewer 负责批评、评分、提出反馈，二者来源于不同厂商/模型以降低同源偏差，并按“写—批—修—再批”循环迭代。

阶段表列出：选题阶段有文献检索、idea creator 和 novelty check；实验阶段有 `experiment-bridge`，从代码审查、GPU 配置、执行到 OOM 处理；自动评审阶段有 auto-review-loop，多轮评分并要求达到门槛；论文写作包含规划、图表、正文、引用审计；rebuttal 包含解析审稿意见、作答和压力测试。

输出包括投稿论文初稿、出版级图表、rebuttal 文稿、会议演示/海报等多种制品。截图中的个别超小字无法可靠确认。

### 图示或结构
ARIS 是覆盖科研生命周期的多阶段 executor/reviewer 闭环，而非单点 idea 工具。

## 04.png

### 新增文字 / 信息
`autoresarch` 被描述为约 630 行 Python 的自主 AI 科研实验框架：给 Agent 一个小而真实的训练环境（示例为 nanochat 简化 GPU 环境），让其连续运行实验并在次日查看日志和更优模型。图片强调该项目不只可用于 LLM，也不必然需要 H100，理论上可用于具有可训练目标的算法迭代。

核心文件分工：`prepare.py` 不修改，负责固定配置、一次性数据准备、训练 BPE tokenizer 和测试工具；`train.py` 由 Agent 编辑，包含模型和训练循环；`program.md` 由人类编辑，给 Agent 研究任务与优化规则。每次实验在固定约 5 分钟预算内运行，用 `val_bpb`（验证集 bits per byte，越低越好）作为与词表大小无关的公平指标。产物是过程和结果：可审查的实验日志、每个 commit 的变更、对应 `val_bpb` 历史。

图片同时给出能力边界：它只处理“可训练模型的自主迭代优化”环节，不做文献检索，不生成想法，不写论文；更像最小科研 demo/实验训练场，而非完整科研 Agent。

### 图示或结构
极简闭环：人写任务规则，Agent 只改训练文件，固定预算实验，单指标比较，日志和提交可回溯。
